## 逐题解析

### 1. 缓存撤权上界（10分）

**题意与考点**：权限缓存最长5分钟，本地会话24小时，API每请求检查缓存；目录离职事件只更新源目录。说明撤权窗口能否只看会话时间，并设计验证。

考点：缓存/会话/撤销。

**参考答案与防御思路**：

1. 若每请求确实查更新后的权限缓存且过期必刷新，资源授权窗口可受5分钟影响，不能机械等于24小时；身份与资源执行点需分别分析。
2. 若缓存刷新失败仍沿用旧值、令牌自带角色绕过检查或存在异步任务，则无该上界，需审查失败策略与全部路径。
3. 用合成离职事件测最后一次被允许到首次拒绝的时间，覆盖新请求、既有会话、批量及任务，并设置可审计目标。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：仅从配置数值推断全系统撤权保证，不验证路径与失败条件。

### 2. 恢复与MFA等级（10分）

**题意与考点**：系统宣称管理员AAL3，但同步通行密钥可用邮件登录同步账号后恢复。依据NIST2025指南评价宣称与改进。

考点：AAL3/同步认证器。

**参考答案与防御思路**：

1. AAL3要求抗钓鱼、不可导出认证密钥等条件，同步认证器不能仅凭公钥登录满足该等级。
2. 审查认证器硬件隔离、注册、恢复和会话要求，选择符合目标的实现，避免按营销名称评级。
3. 为高权限账号建立备用合格认证器、受控恢复与会话撤销，测邮件账号失陷不会直接取得高权限。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把Passkey或MFA字样视为自动合规证明。

### 3. 动态职责分离（10分）

**题意与考点**：系统允许员工兼任采购与审批，业务要求同一笔订单不能自批。怎样区分静态与动态职责约束？

考点：职责分离。

**参考答案与防御思路**：

1. 静态约束可禁止同时分配冲突角色；动态约束可允许不同任务兼任，但限制当前交易中已参与角色。
2. 在服务端把申请人、审批人和交易状态纳入动作规则，处理代理、批量及并发，不能仅依靠UI按钮。
3. 审计角色变更与交易参与，验收自批、代理自批、并发重复及正常他人审批路径。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只创建两个角色却同时赋予全部员工，或把交易角色状态存在客户端。

### 4. 令牌跨协议混淆（10分）

**题意与考点**：同一签名密钥签发登录ID token和邮件确认JWT；应用只验签便创建登录会话。如何建立类型隔离？

考点：JWT BCP/用途分离。

**参考答案与防御思路**：

1. 可信签名只能证明密钥签署，邮件确认与登录有不同目的、受众、有效期和关联状态。
2. 采用互斥验证规则，检查令牌类型、签发者、受众和上下文，必要时分离密钥及接口，拒绝交叉使用。
3. 测试确认令牌不能登录、ID token不能确认错误邮箱、旧令牌失效及密钥轮换，不靠载荷字段存在就推定用途。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：认为同公司同密钥所有JWT可通用。

### 5. 共享服务身份（15分）

**题意与考点**：异步报告服务使用平台管理员身份，队列只写用户ID和报表ID。提出可审计授权委托设计。

考点：工作负载/委托权限。

**参考答案与防御思路**：

1. 服务身份只获得所需基础权限，不使用全局管理员；调用者意图与资源授权需独立绑定。
2. 任务由可信服务创建，记录主体、租户、对象、动作、授权时间与期限，保护队列完整性。
3. 执行时按风险重新检查用户和资源授权或使用受控有限委托，处理离职、对象归属变化与过期任务。
4. 生成文件继续按原主体/租户限权，下载链接短期且不可扩大访问范围，审计关键动作。
5. 验收伪造队列字段、跨租户、离职及重复任务均按策略拒绝或幂等，正常报表可完成。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只信任“队列来自内网”，或用服务管理员权限掩盖调用者的资源边界。

### 6. 属性冲突与缺失（15分）

**题意与考点**：授权条件为“财务部门且受管设备”，目录说财务，设备服务超时；运营提议缺失时按true。设计风险分层。

考点：ABAC失败策略。

**参考答案与防御思路**：

1. 缺失不是条件成立，明确高敏资源默认拒绝并告警，不能在未知时自动声明设备健康。
2. 按资源和动作预定义有限替代路径，如只读低风险摘要或受控应急流程，范围与期限可审计。
3. 治理目录和设备服务来源、签名/认证、时效与缓存，区分已验证的短期旧状态和完全未知。
4. 评估服务高可用与误拒对业务影响，不以可用性之名扩大全部权限。
5. 验收超时、过期、冲突、伪造信号以及恢复后决策更新，记录误拒和未授权放行指标。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把true当作修复依赖不可用的办法，或不说明缓存风险窗口。

### 7. 高风险因素替换（15分）

**题意与考点**：用户先改邮箱，再删除旧认证器，最后用新邮箱恢复。三步各自检查登录状态。说明为何组合流程需额外约束。

考点：状态变更/重新认证。

**参考答案与防御思路**：

1. 被盗会话可能完成整组变更并接管账号，仅存在会话不足以授权改变认证根。
2. 敏感身份变更要求近期合格再认证，关联因素变更与恢复风险，不能让新邮箱立即替代既有可信证明。
3. 向既有可信渠道发通知，设置合适延迟、撤销与风险审查，保留受控丢失因素恢复路径。
4. 注销异常会话与旧因素时核对用户意图，记录变更链和设备风险，不把通知本身当作认证。
5. 验收会话被盗时不能无证据重绑定、合法丢失可恢复、并发变更和撤销传播符合政策。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把每一步“已登录”当成整个身份替换流程安全。

### 8. 零信任项目取舍（15分）

**题意与考点**：半年内只能改造20%资源，如何选择起点并证明有收益，而非为全部请求增加登录弹窗？

考点：风险优先/效果评估。

**参考答案与防御思路**：

1. 按数据敏感度、权限、暴露面与业务影响识别高风险资源、管理身份和第三方通路。
2. 选可治理的试点，建立身份清单、最小权限、可信设备输入和后端执行点，处理旁路与例外。
3. 定义撤权时效、未授权路径拒绝、误拒、业务成功率及故障恢复目标，建立基线。
4. 灰度部署并演练风险变化、IdP中断、信号失效与员工离场，收集可复核证据。
5. 依据结果扩大覆盖并退役过宽规则，报告未覆盖资源和剩余风险，避免只报产品安装率。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：用反复交互替代资源决策，或不说明未覆盖的80%如何处置。
