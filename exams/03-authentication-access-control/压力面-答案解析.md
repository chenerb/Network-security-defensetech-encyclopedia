## 逐题解析

### 1. 登录就是允许吗（10分）

**题意与考点**：面试官：用户已登录，API只要查session就可以了吧？

考点：对象授权。

**参考答案与防御思路**：

1. 会话建立身份，不证明当前对象与动作许可，需服务端检查租户、归属和权限。
2. 统一授权逻辑覆盖单项、批量、后台任务和缓存，默认拒绝未定义路径。
3. 用合成不同权限账号验证允许和拒绝，审计高风险访问。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：网关已验过令牌呢？答：网关认证不能替代后端对象级授权。

**易错点 / 踩坑点**：把入口验证当作所有层的唯一边界。

### 2. 复杂口令还是MFA（10分）

**题意与考点**：面试官：要求16位混合字符并每月换密，还需要MFA吗？

考点：口令/钓鱼。

**参考答案与防御思路**：

1. 复杂度不能抵御所有钓鱼、复用和会话问题，应按风险采用抗钓鱼MFA。
2. NIST2025强调长度、阻止泄露口令与有证据变更，不施加额外组合或无证据周期换密。
3. 同时保护口令存储、限速、注册和恢复，不能只修改用户输入规则。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：用户嫌麻烦？答：优先高风险场景，提供合适认证器与备用方案，用体验和风险数据迭代。

**易错点 / 踩坑点**：只争论字符要求，不分析威胁和全流程。

### 3. OTP是不是无敌（10分）

**题意与考点**：面试官：OTP每30秒换一次，钓鱼还能怎样影响我们？

考点：抗钓鱼。

**参考答案与防御思路**：

1. 人工输入OTP可能被实时转交，一次性不等于绑定真实服务。
2. 抗钓鱼公钥认证可绑定依赖方；部署还需可信注册、端点与恢复机制。
3. 对OTP保留限速、失效及敏感操作再认证，不夸大保障。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：通行密钥一定AAL3？答：同步、硬件隔离与不可导出条件等决定等级，名称不够。

**易错点 / 踩坑点**：把密码新鲜性等同于来源绑定。

### 4. RBAC角色太多（10分）

**题意与考点**：面试官：角色越多越细，为什么我们治理反而困难？

考点：RBAC/ABAC。

**参考答案与防御思路**：

1. 稳定岗位可用角色，部门、地区、设备和资源归属组合全部建角色会膨胀。
2. 可信属性表达动态条件，保持最小权限、职责分离与冲突规则。
3. 建立权限矩阵、测试和定期复核，迁移比较误授误拒。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：ABAC就不用角色了？答：可组合使用，策略复杂度与输入可信度仍需管理。

**易错点 / 踩坑点**：以更换模型名称替代治理。

### 5. SSO集中风险（10分）

**题意与考点**：面试官：SSO省事，为什么安全团队还要求加强IdP管理？

考点：身份枢纽。

**参考答案与防御思路**：

1. IdP是跨应用信任节点，失陷或故障可影响多个系统。
2. 隔离管理员、抗钓鱼MFA、审计、高可用和签名密钥生命周期是核心控制。
3. 应用严格验证令牌并继续资源授权，演练故障与撤销传播。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：每应用自己存一份口令更好吗？答：要比较治理与可用性，复制凭据可能增大泄露面，不能简单排序。

**易错点 / 踩坑点**：只强调便利或只强调集中风险，不给边界与措施。

### 6. OAuth能当登录吗（10分）

**题意与考点**：面试官：拿到access token就证明用户是谁了吧？

考点：OAuth/OIDC。

**参考答案与防御思路**：

1. OAuth主要处理委托授权，认证应用应采用正确身份协议和认证结果验证。
2. OIDC ID token与access token受众、用途不同，不能因JWT格式相同交换。
3. 固定签发者、算法、受众、时间与关联状态，管理回调、PKCE和本地会话。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：验签成功为何仍拒绝？答：错受众、错类型、过期或不对应当前请求，都使结果不适用。

**易错点 / 踩坑点**：只做密码签名验证而忽略协议语义。

### 7. 撤权为什么延迟（10分）

**题意与考点**：面试官：离职账号已禁用，一小时后仍能下载，谁的问题？

考点：撤销路径。

**参考答案与防御思路**：

1. 查现有令牌、本地会话、授权缓存、异步任务和文件链接，禁用目录不自动覆盖它们。
2. 为高风险资源明确撤销目标和传播机制，缩短期限或主动重评估，记录例外。
3. 用真实路径的合成账号测试最后允许与首次拒绝，定位责任执行点。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：每请求问IdP好吗？答：需权衡可用性与时效，可采用受控缓存或撤销事件，但要验证失败策略。

**易错点 / 踩坑点**：只重复“禁用成功”，不查实际访问证据。

### 8. 设备健康从哪来（10分）

**题意与考点**：面试官：客户端送来device_healthy=true，已经HTTPS了还怕伪造吗？

考点：可信属性。

**参考答案与防御思路**：

1. TLS保护传输到当前服务，不保证客户端声明事实真实。
2. 设备信号须来自受控管理或合适证明，认证来源并限制时效，处理缺失与冲突。
3. 高风险访问在未知时受限或拒绝，设置可审计应急流程与误拒监测。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：信号服务挂了？答：按预定风险策略处理，不把未知改成健康。

**易错点 / 踩坑点**：用链路安全替代端点证据。

### 9. 恢复快还是安全（10分）

**题意与考点**：面试官：高管丢手机急着付款，凭工号帮他关MFA可以吗？

考点：高风险恢复。

**参考答案与防御思路**：

1. 公开工号不能证明身份，不能因职位或催促降低边界。
2. 用已注册备用认证器或受控人工核验、审批及有限临时许可，优先保护高风险操作。
3. 撤销遗失因素和相关会话，通知可信渠道，审计并验收恢复。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：没有备用怎么办？答：按预先设计的核验路径推进，必要时暂停敏感操作，避免临时无限放行。

**易错点 / 踩坑点**：把紧急状态当作无证据授权。

### 10. 零信任不是弹窗（10分）

**题意与考点**：面试官：每次请求都再输密码，我们就实现零信任了吗？

考点：架构与体验。

**参考答案与防御思路**：

1. 零信任强调显式、有限资源决策与风险评估，不等于机械重复交互。
2. 管理身份、设备、工作负载、执行点和撤销，网络隔离仍提供补充边界。
3. 以拒绝路径、撤权时效、误拒、业务成功和故障恢复证明改造效果。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：只有预算做一点呢？答：优先管理身份和敏感资源，试点测量后逐步扩大。

**易错点 / 踩坑点**：以交互次数或采购产品代替安全效果。
