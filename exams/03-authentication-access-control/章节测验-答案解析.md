## 逐题解析

### 1. 一次登录的含义（5分）

**题意与考点**：某员工通过SSO认证，随后请求不属于其部门的敏感报告，应依据什么放行？

考点：认证/资源授权。

**正确答案**：C。

**各选项解析**：

- A（错误）：只要SSO成功就放行。身份证明不自动授予对象访问。
- B（错误）：只要来源是内网IP。网络位置不足以建立业务权限。
- C（正确）：服务端检查报告归属、动作及可信角色/属性。具体资源决策才是授权依据。
- D（错误）：只要JWT能解码。解析不能建立可信身份，更不能完成对象授权。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：用统一登录成功替代每个资源的规则。

### 2. 两因素组合（5分）

**题意与考点**：哪项仍然属于单类知识因素？

考点：MFA辨析。

**正确答案**：A。

**各选项解析**：

- A（正确）：口令与童年住址问题。两者都是知道什么，不是独立持有证据。
- B（错误）：硬件密钥与本地激活PIN。可构成持有加知识的多因素认证器，取决于实现。
- C（错误）：口令与独立物理认证器。通常是知识加持有。
- D（错误）：受支持物理认证器与本地生物激活。可构成多因素，需符合具体认证要求。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把几个问题或几个页面当作不同因素。

### 3. 恢复风险（5分）

**题意与考点**：身份提供者已强制硬件MFA，某应用允许邮件链接重置后直接创建管理员会话，主要风险在哪里？

考点：全生命周期一致性。

**正确答案**：D。

**各选项解析**：

- A（错误）：邮件标题太短。不是认证边界核心。
- B（错误）：硬件MFA不可能有任何价值。MFA仍有价值，只是下游弱恢复可绕过。
- C（错误）：管理员会话无需撤销。增加持续风险。
- D（正确）：下游恢复可能降低统一身份的保障。应用自建恢复需与高风险身份策略一致，限制会话与权限。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：只检查IdP登录，不检查各应用的备用入口。

### 4. ABAC信号（5分）

**题意与考点**：零信任策略接受客户端提交device_healthy=true，主要问题是什么？

考点：属性信任。

**正确答案**：B。

**各选项解析**：

- A（错误）：布尔值不允许用在策略中。布尔值可用，问题是来源可信度。
- B（正确）：调用者可控制策略关键输入。需来自受管设备证明或受控服务，并考虑时效。
- C（错误）：换字段名字即可解决。命名不建立可信来源。
- D（错误）：只要有HTTPS就不会伪造内容。TLS保护传输，不保证客户端声明真实。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：用传输安全替代属性真实性。

### 5. 令牌替换（5分）

**题意与考点**：API接收为另一个客户端签发的ID token，仅验签后作为API通行证，缺什么？

考点：令牌类型/受众。

**正确答案**：C。

**各选项解析**：

- A（错误）：只缺少压缩。与验证目标无关。
- B（错误）：需要公开私钥。破坏签名。
- C（正确）：正确令牌类型、受众和资源授权验证。有效签名不授权错误接收者使用身份令牌。
- D（错误）：无需修改，因为来自同IdP。同签发者仍会给不同接收方不同用途令牌。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把信任同一IdP当作信任其全部令牌用于所有接口。

### 6. SSO撤销（5分）

**题意与考点**：若本地会话有效24小时，而IdP账号已禁用，如何限制残余访问？

考点：会话撤销传播。

**正确答案**：A。

**各选项解析**：

- A（正确）：缩短或按风险管理会话并接入撤销/重评估机制。需明确执行点与传播时限，测试已建立会话。
- B（错误）：仅删除浏览器书签。不影响会话凭证。
- C（错误）：继续延长令牌。扩大残余窗口。
- D（错误）：只改用户显示名。不改变授权状态。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：只观察新登录失败，不测既有会话。

### 7. 默认拒绝（5分）

**题意与考点**：授权服务无法判断高风险导出权限时，哪项更合适？

考点：失败策略。

**正确答案**：D。

**各选项解析**：

- A（错误）：默认允许便于连续性。可能把故障变成未授权数据泄露。
- B（错误）：把导出按钮变灰但后端仍放行。未建立后端边界。
- C（错误）：将所有人升为管理员。完全扩大风险。
- D（正确）：按预定策略拒绝高风险操作并告警。可对不同风险预先设计受控应急路径，不任意全放。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把可用性需求解释成无限权限。

### 8. 角色治理（5分）

**题意与考点**：哪项最能减少长期权限累积？

考点：最小权限/生命周期。

**正确答案**：B。

**各选项解析**：

- A（错误）：所有临时角色永久保留。不断累积权限。
- B（正确）：设置责任人、到期回收和定期复核。结合岗位变化与实际使用删除不必要许可。
- C（错误）：角色越多越安全。数量不说明范围和冲突。
- D（错误）：离职仅收回工牌。数字会话与后台身份仍可能存活。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：以配置过权限代替持续维护。

### 9. 权限模型选型（6分）

**题意与考点**：比较共享文档、岗位权限和分级档案三种场景的模型倾向与限制。

考点：DAC/RBAC/MAC。

**参考答案与防御思路**：

1. 共享文档可采用DAC，但需限制公开分享与转授权，并管理所有者变更。
2. 岗位权限适合RBAC，动态资源条件可结合ABAC，并检查互斥职责和角色爆炸。
3. 分级档案可使用强制标签策略，普通所有者不能放宽；仍需准确分类与系统完整执行。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：强行认为一个模型能覆盖所有细节，或只选名称不写边界。

### 10. 因素与信号（6分）

**题意与考点**：设备风险分数、地理位置与生物激活是否都可直接算成新的认证因素？

考点：认证保障/上下文。

**参考答案与防御思路**：

1. 风险分数和地理位置是辅助信号，不自动成为独立认证因素，来源与误判需治理。
2. 生物特征通常作为物理认证器的激活因素，不能机械当作独立可保密秘密。
3. MFA需按知识、持有及生物等因素与具体协议建立证明；信号可触发进一步认证或限权。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：以信号数量宣称更高AAL，不核对标准要求。

### 11. 令牌检查清单（6分）

**题意与考点**：列出OIDC客户端验证ID token的关键类别，不必写协议实现。

考点：OIDC验证。

**参考答案与防御思路**：

1. 限定可信签发者、允许算法和可信密钥，验证签名而非仅解码；密钥轮换受控。
2. 验证aud、时间等声明，按流程检查nonce或请求关联，确保结果对应预期客户端与登录。
3. 严格重定向地址与安全授权码流程、PKCE及会话管理，API不要错用ID token进行资源授权。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：列出签名后省略受众、关联与会话。

### 12. 零信任验收（6分）

**题意与考点**：给出衡量零信任改造的三个可检查结果。

考点：架构效果。

**参考答案与防御思路**：

1. 高风险资源都有显式身份及动作授权，未授权路径和可信属性伪造测试被拒。
2. 风险变化、设备失效或离职能在约定期限撤销访问，令牌、会话和缓存传播可测量。
3. 正常业务成功率、误拒和故障恢复达到目标，例外有期限和责任人，日志能定位决策。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：用采购产品数量或每次输入密码次数衡量架构完成。

### 13. 调岗残留权限（12分）

**题意与考点**：财务员工调到销售，目录已换部门，但仍拥有旧角色、导出任务和24小时会话。设计最小权限处置。

考点：身份/角色/异步撤销。

**参考答案与防御思路**：

1. 关联岗位变更事件，撤销旧角色和冲突职责，依据新岗位明确所需权限，保留变更审计。
2. 使部门等属性来自可信目录并及时更新，授权缓存设时限或主动刷新，不信任客户端值。
3. 终止或重新评估旧会话、令牌和后台导出任务，检查下载文件的独立权限与有效期。
4. 验收新岗位正常访问、旧敏感操作被拒、异步任务不继续越权，记录传播时效与遗留例外。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只改部门字段，不清除既有角色和任务身份。

### 14. SSO集中故障（12分）

**题意与考点**：IdP不可用，团队拟临时把管理后台加到免登录名单。设计替代连续性方案。

考点：IdP/应急访问。

**参考答案与防御思路**：

1. 依据资产风险拒绝任意免登录管理；评估哪些既有低风险会话可按原期限继续，哪些操作应暂停。
2. 使用事先设计的受控应急身份、独立强认证和限定权限，设置审批、期限与人员分离。
3. 切换高可用或恢复IdP，审计应急访问并监测异常，禁止在故障中扩大所有用户范围。
4. 验收故障期间未授权管理被拒、必要业务可受控进行，恢复后核销临时身份和审计全部操作。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：临时免登录没有到期、没有操作范围、没有审计。

### 15. 多租户联合身份（12分）

**题意与考点**：平台接受客户自建IdP；只验签就把声明role=admin映射为平台超级管理员。设计租户隔离。

考点：联合身份/属性映射。

**参考答案与防御思路**：

1. 每租户受控注册可信IdP、受众与密钥，建立客户主体到该租户范围内身份映射，拒绝未知签发者。
2. 声明必须按协议验证，但客户role仅在批准映射范围内生效，不能授予平台全局管理员。
3. 后端每请求检查租户、对象与动作，高风险平台权限由独立内部授权流程管理。
4. 验收错误受众、跨租户主体、任意角色值与离场IdP被拒，测试缓存与既有会话的撤销。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把客户可签署的属性直接升级为平台管理权。
