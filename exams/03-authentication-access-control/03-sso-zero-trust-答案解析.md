## 逐题解析

### 1. OAuth与OIDC（8分）

**题意与考点**：哪项正确描述OAuth2.0与OIDC？

考点：联合身份分工。

**正确答案**：B。

**各选项解析**：

- A（错误）：OAuth任何access token都能直接证明登录身份。委托授权令牌不自动满足认证结果验证要求。
- B（正确）：OIDC在OAuth上增加身份层及ID token语义。客户端需按OIDC验证身份结果，API按资源规则接受access token。
- C（错误）：OIDC完全不需要HTTPS。安全通信仍是协议与部署基础。
- D（错误）：SSO代表全部应用永久授权。统一认证不消除资源授权与会话期限。

**评分**：选对得8分；错选、不选不得分。

**易错点 / 踩坑点**：把授权与认证因同处登录流程而混为一谈。

### 2. JWT验证（8分）

**题意与考点**：应用只解码JWT并读取用户名，未验签。缺少哪项？

考点：令牌验证。

**正确答案**：A。

**各选项解析**：

- A（正确）：所有必要可信验证，包括签名、iss、aud和时间等。解码只是解析，不能建立可信签发者与目标绑定。
- B（错误）：只缺少更美观的编码。显示与信任无关。
- C（错误）：只需延长有效期即可。延长未验证令牌不会增加可信性。
- D（错误）：JWT不允许携带用户名。可携带相应声明，问题是未验证来源与用途。

**评分**：选对得8分；错选、不选不得分。

**易错点 / 踩坑点**：把三段可读文本当作已经可信的身份断言。

### 3. PKCE（8分）

**题意与考点**：授权码流程中PKCE主要提供哪项关联保护？

考点：OAuth安全流程。

**正确答案**：D。

**各选项解析**：

- A（错误）：自动赋予用户管理员权。PKCE不决定业务权限。
- B（错误）：加密全部JWT载荷。PKCE不是JWT加密方案。
- C（错误）：取代服务器证书验证。传输认证仍需要TLS。
- D（正确）：把码兑换绑定到发起方掌握的验证秘密。提高授权码被截取后滥用兑换的难度，仍需其他协议控制。

**评分**：选对得8分；错选、不选不得分。

**易错点 / 踩坑点**：把单个流程控制当作对回调、令牌与权限的完整替代。

### 4. 零信任（8分）

**题意与考点**：哪项更符合零信任原则？

考点：显式资源决策。

**正确答案**：C。

**各选项解析**：

- A（错误）：内网IP的用户无需认证。网络位置不能独立建立信任。
- B（错误）：每次点击都要求手输密码。持续评估不等于机械重复交互。
- C（正确）：基于身份、设备与资源风险进行显式有限授权。结合可信信号及执行点管理范围、期限与风险变化。
- D（错误）：部署一台设备即可完全完成。架构涉及身份、资源、流程与治理。

**评分**：选对得8分；错选、不选不得分。

**易错点 / 踩坑点**：把产品名称或频繁登录当作架构成果。

### 5. 禁用与会话（8分）

**题意与考点**：IdP禁用员工账号后，资源仍接受未过期令牌，说明什么？

考点：撤销时效。

**正确答案**：B。

**各选项解析**：

- A（错误）：账号禁用必然失败。新认证可能已被拒，但既有令牌有独立生命周期。
- B（正确）：必须治理令牌、本地会话和缓存的撤销传播。禁用事件需要到达各执行点或由短期限限制残余窗口。
- C（错误）：应永久保留令牌。这扩大了撤权风险。
- D（错误）：所有签名密钥必须每天公开私钥。公开私钥破坏签名，且不是撤销用户会话的方法。

**评分**：选对得8分；错选、不选不得分。

**易错点 / 踩坑点**：把身份目录状态当作全局瞬时权限状态。

### 6. 令牌职责（15分）

**题意与考点**：解释ID token与access token的接收方和用途差异。

考点：令牌类型隔离。

**参考答案与防御思路**：

1. ID token向特定OIDC客户端表达认证结果，需验证签发者、受众、时间和请求关联等条件。
2. access token供目标资源服务判断委托访问，接受范围由资源与授权协议规定，不能任意用于客户端登录。
3. 不同类型应有独立验证规则与受众；不把“签名有效”当作可在任何系统通用。

**评分要点**：按上述3项分别给5、5、5分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：混淆两种令牌，只依据同一JWT外形决定接收。

### 7. IdP故障（15分）

**题意与考点**：身份服务中断时，为什么不能临时让所有内部请求免认证？

考点：可用性与边界。

**参考答案与防御思路**：

1. 免认证把关键边界彻底移除，可能使故障成为未授权访问机会。
2. 预先按资源风险设计现有会话期限、受限应急身份与人工审批；高风险操作可暂停，新授权不任意开放。
3. 演练故障切换、日志记录、例外到期和恢复后的核销，权衡业务连续性而非临时无限放行。

**评分要点**：按上述3项分别给5、5、5分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把故障放行当作任何资源都可采用的默认策略。

### 8. 供应商远程访问（30分）

**题意与考点**：供应商经SSO连接后可访问整个研发网；设备状态仅客户端提交。设计限权方案与验收。

考点：SSO/零信任/可信属性。

**参考答案与防御思路**：

1. 盘点供应商任务与目标资源，把认证成功与研发网许可分离，关闭不必要的网络可达路径。
2. 使用短期身份与抗钓鱼MFA，严格验证签发者、受众、回调和令牌类型，限制会话期限。
3. 设备信号来自受控且有时效的来源，信号缺失或过期按风险拒绝或限制，不接受自由声明。
4. 策略执行点只放行指定应用、操作和时段，后端继续检查对象授权，高风险行为再认证并审计。
5. 验收错误受众被拒、伪造设备值无效、未授权资源不可达、合同结束和风险变化后权限按时撤销。

**评分要点**：按上述5项分别给6、6、6、6、6分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把SSO当作全网信任票，或只加设备字段而不保证属性来源。
