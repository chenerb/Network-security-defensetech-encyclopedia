## 逐题解析

### 1. HTTPS就安全吗（10分）

**题意与考点**：面试官：全站HTTPS，为什么还要做Web安全？

考点：链路/应用边界。

**参考答案与防御思路**：

1. TLS保护具体连接并验证对端，不审查应用业务、授权和终端。
2. 继续做对象授权、输入处理、会话及供应链控制，检查代理到后端链路。
3. 以错误证书拒绝及业务安全测试验收，锁标志不担保商家诚信。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：mTLS是否可省登录？答：证书可作为认证输入，但仍需身份映射、生命周期及业务授权。

**易错点 / 踩坑点**：用“HTTPS安全”替代完整威胁模型。

### 2. 证书报错怎么修（10分）

**题意与考点**：面试官：紧急上线证书错误，先关验证能省时间，你怎么处理？

考点：可信对端。

**参考答案与防御思路**：

1. 关闭验证丢失对端身份边界，先定位名称、链、有效期、用途与时钟。
2. 修复证书、目标或受控信任分发，测试环境使用隔离CA配置，避免带入生产。
3. 设置自动续期、告警和负责人，验收错误证书拒绝与正常客户端兼容。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：内网能例外吗？答：网络位置不替代身份，可用私有CA或明确受控信任，不直接关闭。

**易错点 / 踩坑点**：以紧急或内网为由永久绕过验证。

### 3. 0-RTT的代价（10分）

**题意与考点**：面试官：TLS1.3更安全，0-RTT付款当然也更安全吧？

考点：早期数据。

**参考答案与防御思路**：

1. 更高版本不意味着所有可选特性都有相同新鲜性保证，0-RTT可能被重放。
2. 敏感写操作等待完整握手或采用严谨适用策略，业务仍有幂等与状态检查。
3. 验证跨节点重复、并发和重启，不能只看单请求延迟。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：只GET可安全吗？答：需确认GET真正无副作用，不按方法名字假定业务行为。

**易错点 / 踩坑点**：用协议版本替代具体特性的威胁分析。

### 4. 防火墙为什么漏（10分）

**题意与考点**：面试官：只允许443，恶意请求还能进来吗？

考点：网络/应用。

**参考答案与防御思路**：

1. 443允许的是连接路径，应用操作仍可能越权或错误处理输入。
2. 加密可能限制网络载荷可见性，需要后端防御与应用、身份、终端日志。
3. 最小跨区和出站限制缩小范围，但不承诺修复所有允许流量。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：装下一代防火墙呢？答：核对真实可见性与规则效果，产品名不消除应用职责。

**易错点 / 踩坑点**：把端口分类当作所有内容已安全。

### 5. IDS和IPS怎么选（10分）

**题意与考点**：面试官：IPS能拦截，所以一定优于IDS吗？

考点：响应权限。

**参考答案与防御思路**：

1. IDS观察告警，IPS可影响流量；自动阻断增加响应速度也增加误伤与故障代价。
2. 依据资产风险、可用性、规则证据和覆盖，先观察验证再有限灰度。
3. 设置高可用、失败策略、回滚与责任人，量测漏报和业务影响。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：fail-open还是fail-closed？答：按风险和替代防线预先决定，并演练，不给全网统一答案。

**易错点 / 踩坑点**：将越积极阻断等同越安全。

### 6. 没有告警安全吗（10分）

**题意与考点**：面试官：我们连续一周零告警，说明防御很好？

考点：覆盖与证据。

**参考答案与防御思路**：

1. 可能是无事件，也可能采集失败、规则失效或覆盖遗漏，需要先确认观测。
2. 检查探针位置、丢包、时间和规则更新，用授权合成事件验证。
3. 关联终端、应用和身份数据，说明盲区并报告处理指标。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：有一万告警更好吗？答：数量不说明真实性、遗漏或响应效果，需要标签与运营结果。

**易错点 / 踩坑点**：用静默或噪声直接推断安全。

### 7. VPN就是可信内网（10分）

**题意与考点**：面试官：员工MFA登录VPN后，我们可以开放整个研发网吗？

考点：隧道/最小权限。

**参考答案与防御思路**：

1. 认证与通道不证明终端完全健康，也不授予所有资源许可。
2. 限制身份、设备、路由、时段与目标，后端继续对象与操作授权。
3. 检查DNS、IPv6、分流、断线和撤销，维护网关及管理面。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：站点互联怎么做？答：限定两端子网与服务依赖，网关后仍分区与保护。

**易错点 / 踩坑点**：把进入隧道等同进入无边界可信区。

### 8. DDoS本机能救吗（10分）

**题意与考点**：面试官：带宽被打满，我把主机过滤开到最强会恢复吗？

考点：缓解位置。

**参考答案与防御思路**：

1. 坏流量在到主机前已占接入链路，本机处理太晚，需上游/边缘协作。
2. 提前约定引流、容量、DNS和源站入口，明确联系人与费用。
3. 同时保护应用依赖，衡量业务成功率、延迟和误伤，不只看丢弃比例。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：黑洞呢？答：可保护共享基础设施，却也放弃目标合法访问，需授权范围和恢复条件。

**易错点 / 踩坑点**：只看服务器CPU或丢包，不看拓扑瓶颈。

### 9. CDN为什么不够（10分）

**题意与考点**：面试官：首页上了CDN，为什么登录和提交还超时？

考点：缓存/动态依赖。

**参考答案与防御思路**：

1. 静态缓存不覆盖所有动态请求，登录、写接口或源站直连仍可消耗资源。
2. 定位数据库、线程、连接和外部API，限制并发与重试，使用缓存、队列、幂等和熔断。
3. 限制源站入口并设置分层配额与预算，检查核心交易而不是主页。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：按IP限流行吗？答：考虑共享NAT误伤和分散请求，结合账号、接口与成本。

**易错点 / 踩坑点**：买边缘服务后忽略动态路径和真实瓶颈。

### 10. 如何证明改善（10分）

**题意与考点**：面试官：安全改造上线后如何证明网络更安全，而不是更慢？

考点：验收/权衡。

**参考答案与防御思路**：

1. 定义允许与拒绝路径、检测覆盖、撤销时效、业务成功和性能基线。
2. 用受控合成场景和故障演练验证错误证书、未授权路径、规则误阻与容量恢复。
3. 结合日志、误伤、费用与残余盲区迭代，明确负责人和例外期限。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**可能追问与应答方向**：追问：测试全过是否绝对安全？答：只证明已定义范围，报告未覆盖条件并持续复核。

**易错点 / 踩坑点**：只报采购、规则数或流量拦截量，没有可复核业务结果。
