## 逐题解析

### 1. 各层职责（5分）

**题意与考点**：为远程管理API选择防御组合，哪项分工准确？

考点：TLS/VPN/授权。

**正确答案**：D。

**各选项解析**：

- A（错误）：TLS负责所有业务权限。TLS认证与通道保护不定义全部对象规则。
- B（错误）：VPN连接后可取消MFA。隧道不替代用户认证。
- C（错误）：防火墙可以修复所有应用漏洞。网络策略限制可达性，不能修复全部代码问题。
- D（正确）：TLS保护连接、网络限制可达性、后端检查资源权限。各层相互补充，并需检测和生命周期治理。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把一个网络产品当作完整应用安全。

### 2. 协议版本（5分）

**题意与考点**：新公网服务面对维护中的客户端，默认策略更合理的是哪项？

考点：TLS版本治理。

**正确答案**：A。

**各选项解析**：

- A（正确）：优先TLS1.3，必要时按RFC9325安全配置TLS1.2。结合兼容验证，移除已弃用版本与弱选项。
- B（错误）：为兼容默认SSLv3。旧协议不适合当前安全基线。
- C（错误）：把所有证书验证都关闭。失去对端身份。
- D（错误）：只开放TLS1.0并称最新。版本与事实不符。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：只讨论协议名字，不考虑配置和客户端。

### 3. 监测位置（5分）

**题意与考点**：边界IDS可看到互联网流量，但内部数据库访问未经过该探针，如何描述覆盖？

考点：检测盲区。

**正确答案**：C。

**各选项解析**：

- A（错误）：已覆盖全网。内部未经过的数据不能假定被观察。
- B（错误）：未看到告警说明内部安全。没有观测不等于没有事件。
- C（正确）：需增加关键跨区或主机数据源并说明现有范围。按资产威胁与路径配置覆盖。
- D（错误）：将告警阈值降到0就能看到内部。阈值不能创造未采集的数据。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把告警静默当成安全证据。

### 4. 分区与路由（5分）

**题意与考点**：云安全组只约束IPv4，服务同时开放IPv6，主要应检查什么？

考点：多路径边界。

**正确答案**：B。

**各选项解析**：

- A（错误）：IPv6名字更长因此更安全。地址格式不提供访问许可。
- B（正确）：所有地址族与执行点的实际可达性和策略。另一地址族可成为遗漏路径，需统一验证。
- C（错误）：只增加一条IPv4重复规则。不能约束IPv6路径。
- D（错误）：关闭日志即可提升防护。减少观测不解决策略遗漏。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：只依据一个地址族的测试宣称隔离完成。

### 5. 网关之后（5分）

**题意与考点**：站点VPN在网关结束，内部应用明文传输敏感数据，哪项正确？

考点：保护范围。

**正确答案**：D。

**各选项解析**：

- A（错误）：公网有隧道所以内部自动加密。网关后不在原隧道保护范围内。
- B（错误）：只要换VPN品牌就解决。部署边界才是问题。
- C（错误）：明文可替代应用权限。概念错误。
- D（正确）：按风险补充内部TLS与身份、授权控制。明确两端保护、分区和应用规则。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：只看公网段，不追踪端到端数据路径。

### 6. 阻断规则上线（5分）

**题意与考点**：新IPS规则将异常连接全部阻断，怎样降低正常业务中断风险？

考点：灰度/误报。

**正确答案**：A。

**各选项解析**：

- A（正确）：先观察验证，再有限灰度并准备回滚。结合证据、误报样本、性能和故障策略。
- B（错误）：立刻全网上线不保留日志。难以定位误阻与恢复。
- C（错误）：异常都是确定恶意。基线偏差可能正常。
- D（错误）：用更高告警音量代替测试。无助于阻断准确性。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：以主动阻断数量衡量成效。

### 7. 可用性指标（5分）

**题意与考点**：DDoS清洗后流量下降90%，但支付仍失败，合理评价是什么？

考点：业务验收。

**正确答案**：C。

**各选项解析**：

- A（错误）：防御已完全成功。实际关键业务仍不可用。
- B（错误）：拦截比例就是唯一目标。忽略误伤和剩余瓶颈。
- C（正确）：继续定位依赖瓶颈与误伤，衡量有效交易成功率。结果应关注真实业务、延迟、错误和成本。
- D（错误）：停止所有监测。无法确认恢复。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：把网络计数当作业务结果。

### 8. 高峰与攻击（5分）

**题意与考点**：网络高峰同时导致DNS延迟、连接表耗尽，最合理行动是什么？

考点：资源定位。

**正确答案**：B。

**各选项解析**：

- A（错误）：只看应用CPU。遗漏网络与依赖资源。
- B（正确）：先保护关键瓶颈并采集证据，再调整分层缓解。过载无论是否恶意都需要韧性；定性结合更多信息。
- C（错误）：未经检查封禁全地区。可能大面积误伤。
- D（错误）：重置全部用户口令即可。无法直接恢复资源容量。

**评分**：选对得5分；错选、不选不得分。

**易错点 / 踩坑点**：为追求先定性而迟迟不保护可用性。

### 9. 边界逐段画（6分）

**题意与考点**：说明客户端、VPN网关、TLS代理和应用之间各自的保护边界。

考点：端点与路径。

**参考答案与防御思路**：

1. VPN只保护按路由进入隧道的流量到隧道端点，分流和网关后需单独检查。
2. TLS保护相应连接到终止点，代理到后端要另建保护并验证服务身份。
3. 应用仍执行身份映射、对象授权与安全处理，网络连接或双向证书不能提供无限权限。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：画一个“加密”标签覆盖所有终止后的链路。

### 10. 采集与隐私（6分）

**题意与考点**：TLS加密让IDS缺少载荷时，如何改进而不默认集中解密全部数据？

考点：互补可见性。

**参考答案与防御思路**：

1. 说明网络元数据能看什么、不能看什么，检查采集位置、丢包与时间同步。
2. 结合应用、身份和终端日志构成证据，限制敏感字段记录并管理访问与留存。
3. 仅在有明确需求的受控范围评估解密，权衡证书信任、隐私、性能与新增集中风险。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把解密全部流量当作检测唯一办法，或隐藏覆盖限制。

### 11. 分层DDoS方案（6分）

**题意与考点**：分别说明带宽饱和与数据库连接耗尽的主要缓解位置。

考点：DDoS分层。

**参考答案与防御思路**：

1. 带宽饱和需要在上游或边缘拥塞前过滤、分散与协作，本机丢包已经太晚。
2. 数据库连接耗尽需要限制昂贵接口并发、超时、缓存、队列、幂等和依赖隔离。
3. 结合源站入口、DNS和费用上限，持续检查正常业务成功与误伤，不能只用扩容处理全部层。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：花钱扩同一个非瓶颈资源，或没有恢复条件。

### 12. 防火墙审计（6分）

**题意与考点**：审计规则多年增长的网络应检查哪三类问题？

考点：策略治理。

**参考答案与防御思路**：

1. 过宽来源/目标/端口、无责任人或失效临时规则，确认业务依据和真实依赖。
2. 规则顺序、状态返回、IPv6、云与主机执行点的差异，确保没有未受控路径。
3. 允许/拒绝测试、日志和回滚，兼顾罕见任务与业务连续性，再受控删除。

**评分要点**：按上述3项分别给2、2、2分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：直接删除零命中规则而未考虑灾备或周期任务。

### 13. 远程运维改造（12分）

**题意与考点**：公司拟用VPN和mTLS保护数据库管理，同时计划取消资源权限检查。设计正确分工与验收。

考点：认证/网络/授权。

**参考答案与防御思路**：

1. VPN限制受管运维身份、设备和必要路由，管理面与普通业务分区，不开放整个内网。
2. mTLS认证具体客户端或工作负载，治理证书信任、用途、轮换和撤销，并保护完整链路。
3. 保留数据库与管理应用最小权限、动作授权和高风险审批，证书身份映射为有限角色。
4. 验收未知证书、离职身份、未授权数据库和危险操作被拒，正常维护成功，故障与撤销时效可测。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把两个认证/通道机制叠加当作取消授权的理由。

### 14. 全网IPS误阻（12分）

**题意与考点**：内联IPS在流量高峰故障，默认拒绝导致核心业务全部中断。制定恢复与长期防御设计。

考点：IPS可用性。

**参考答案与防御思路**：

1. 启动已授权恢复与回滚流程，保留性能、故障和规则证据，监控实际业务影响并通知责任角色。
2. 按风险选择高可用、故障放行或拒绝及受控备用路径，明确放行窗口的补充检测和期限。
3. 复核容量、采集丢包和规则成本，观察/灰度新规则，区分已知高可信威胁与一般异常。
4. 受控演练高峰、节点故障和误阻，验证恢复时间、正常成功率和剩余威胁可见性，更新预案。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：临时永久旁路而不恢复保护，或只换故障模式不解决容量。

### 15. 促销期间过载（12分）

**题意与考点**：促销API延迟升高，上游平稳但数据库饱和；同时IDS告警量增大，主页仍正常。制定协同处置。

考点：DDoS/检测/业务。

**参考答案与防御思路**：

1. 建立统一时间线，关联促销与告警，定位数据库和昂贵接口，采集必要日志而不单凭量大定性。
2. 应用层限制并发、重试和高成本请求，缓存可缓存内容，队列与降级保留核心交易，设置预算。
3. 检测团队分级关联告警，防止拒绝服务分散注意力而遗漏其他事件；仅对高可信规则受控阻断。
4. 验收交易成功率、延迟、误伤、依赖容量和费用，促销后撤销临时规则并复盘，不以主页可用代替全部业务。

**评分要点**：按上述4项分别给3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：网络、安全和应用各自只报局部指标，没有共同恢复目标。
