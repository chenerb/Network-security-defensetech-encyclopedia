## 逐题解析

### 1. 有限链路与清洗位置（10分）

**题意与考点**：源站接入容量1Gbit/s，事件流量3Gbit/s；主机丢弃90%坏流量。无需生成流量，解释为何仍可能失效并提出拓扑验收。

考点：上游拥塞。

**参考答案与防御思路**：

1. 超过1G的流量在到达主机前竞争链路，主机丢弃不能回收已经占用的上游容量，百分比不代表合法流量可达。
2. 与上游或边缘清洗协作，在拥塞前过滤或分散，限制源站只接受批准入口，同时保护DNS及管理路径。
3. 用合同能力、受控演练与外部业务探测检查引流、容量、恢复及误伤，关注成功请求而非仅本机丢包。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：用主机过滤比例证明上游没有瓶颈。

### 2. 稀有事件的误报负担（10分）

**题意与考点**：一天100万条连接，真实目标事件100条；检测召回率90%，正常连接误报率0.1%。估计告警精确率并解释运营意义。

考点：基率/检测指标。

**参考答案与防御思路**：

1. 真阳性约90条；正常连接999900条，误报约999.9条，告警合计约1089.9，精确率约8.26%。
2. 正常流量基数很大，所以看似低误报率仍产生约千条误报；召回高不意味着调查负担小。
3. 需定义事件范围与标签，按资产、上下文和规则证据关联分级，设置处理能力；不能为了降量盲目牺牲所有覆盖。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：将误报率0.1%直接说成告警99.9%可信。

### 3. 不对称路径（10分）

**题意与考点**：一个连接的请求经过探针A，返回经过探针B；系统称有状态分析仍完整。如何审查与改进？

考点：状态与采集拓扑。

**参考答案与防御思路**：

1. 有状态协议分析依赖完整或协调的双向状态，分散且不共享上下文可能产生误报、漏报或重组失败。
2. 盘点实际路由、镜像、负载均衡和时间同步，采用合适流量分配或状态关联并测丢包，不仅查看设备在线。
3. 在授权合成连接中验证完整会话、变路、峰值与节点故障，说明不能覆盖的路径，结合主机/应用证据。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：根据采购说明书的“有状态”功能推断所有拓扑都能正确分析。

### 4. 隧道与DNS故障（10分）

**题意与考点**：全隧道客户端IPv4走公司网关，IPv6直出；断线后DNS缓存仍指内部地址。说明风险与可检验策略。

考点：多地址族/断线。

**参考答案与防御思路**：

1. “全隧道”目标未实际覆盖IPv6，部分流量可能绕过出口策略；DNS与路由不一致会泄露查询或造成错误访问。
2. 明确所有地址族、DNS、缓存、路由与断线行为，按风险选择受控阻断或允许范围，不能只关闭一个地址族的日志。
3. 用合成目标验证IPv4/IPv6、解析、断线、重连和睡眠唤醒的路径，记录可用性与不符合政策时的业务处置。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只在正常连接时测试一条IPv4地址。

### 5. 0-RTT与幂等边界（15分）

**题意与考点**：支付API使用0-RTT并按请求ID去重；请求ID存储在单机内存，多节点各自执行。分析是否足够及整改。

考点：重放/分布式幂等。

**参考答案与防御思路**：

1. 早期数据存在重放风险，单机去重不能约束多节点，重启也可能丢失状态，不能认定只执行一次。
2. 默认拒绝敏感支付早期数据，等握手完成；业务层仍需要并发、重试与重复操作控制。
3. 使用共享且原子的幂等记录与订单状态约束，绑定用户、金额和操作，不仅任意请求ID。
4. 限定状态留存、失败重试、事务边界与恢复，避免先付款后记ID造成竞态。
5. 验收跨节点、并发、重启、网络重试与同订单不同ID，确认不重复扣款且可恢复合法交易。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把一个内存集合或TLS完整性作为分布式业务幂等的充分条件。

### 6. 加密检测取舍（15分）

**题意与考点**：安全团队要求解密全部员工TLS流量以提高IDS覆盖；研发强调隐私、证书与性能风险。设计可评审方案。

考点：可见性/集中风险。

**参考答案与防御思路**：

1. 先定义需要检测的资产与行为、现有盲区和合适数据源，说明解密不是所有威胁的必要或充分条件。
2. 优先评估应用、终端、身份和连接元数据，按最小数据原则收集，保护日志权限与留存。
3. 如确需受控解密，限定范围并评估适用要求、信任根分发、敏感业务例外与私钥集中风险。
4. 容量、故障与协议兼容要验证，mTLS和其他不可检查路径需明确说明，禁止悄悄降级客户端验证。
5. 以检测收益、误报、业务成功、性能和数据暴露评审试点，保留回滚与安全退出路径。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只谈检测覆盖，忽视新增信任根和明文集中存储风险。

### 7. 防火墙与依赖故障（15分）

**题意与考点**：默认拒绝后证书续期、时间同步和软件更新失败；团队准备开放任意出站443。设计兼顾安全与维护方案。

考点：依赖/最小出站。

**参考答案与防御思路**：

1. 列出维护任务依赖、目的和负责人，分析DNS、时间、CA验证与更新源，不把所有失败都归为同一端口。
2. 通过受控出口、代理或批准目标范围放行必要业务，适配动态地址与身份，避免无期限任意出站。
3. 保留应用层验证和供应链签名，网络放行不等于更新源可靠；维护流程按最小权限执行。
4. 设置临时例外期限、日志和回滚，监控续期到期风险与配置漂移，确保可审计。
5. 验收正常续期、校时和更新成功，非必要外联被拒，灾备路径可用，删除例外不会影响预定任务。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：以紧急维修名义永久开放万能规则，或只看端口不看目的。

### 8. 安全与费用共同恢复（15分）

**题意与考点**：高峰期间自动扩容维持200响应，但有效交易降至20%，外部依赖费用增长十倍。提出恢复目标与动作顺序。

考点：业务韧性/成本。

**参考答案与防御思路**：

1. 200响应不足以说明业务成功，定义有效交易成功率、延迟、错误、依赖容量及预算，并建立事件时间线。
2. 限制昂贵接口并发、重试和依赖配额，采用队列、缓存、幂等与熔断，优先核心流程。
3. 与边缘和供应商协调异常请求过滤，识别热门合法流量，按账号、接口和成本限速，监控共享出口误伤。
4. 设置自动扩容与费用上限、审批及降级策略，避免扩大应用规模后继续压垮外部依赖。
5. 受控验证业务恢复与成本下降，分阶段撤销临时规则并持续监测其他事件，记录残余风险。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把流量、实例数或HTTP成功码当成唯一恢复指标。
