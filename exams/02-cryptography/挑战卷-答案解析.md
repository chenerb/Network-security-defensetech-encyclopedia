## 逐题解析

### 1. 随机nonce估算（10分）

**题意与考点**：某密钥下生成2000个独立均匀96位nonce。用生日界估计碰撞概率量级，并说明该结果为何不等于完整GCM安全保证。

考点：概率/模式限额。

**参考答案与防御思路**：

1. 稀疏抽样近似为n(n−1)/(2×2^96)，这里约2000×1999/2^97，约2.5×10^−23。假设独立均匀且消息数远小于空间。
2. 概率小不是零，随机源失败、跨实例错误、备份回滚可破坏模型，必须验证实现前提。
3. GCM还有总处理量、标签、验证尝试与具体规范限额；应按标准和库管理使用上限、轮换与认证失败。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把理想概率估算当作可无限生成数据的许可证。

### 2. 租户独立计数（10分）

**题意与考点**：租户A和B各自从0递增nonce，但共用同一GCM密钥。产品认为“租户不同所以不重复”。评价并设计约束。

考点：密钥作用域/nonce。

**参考答案与防御思路**：

1. 同密钥下计数值相同仍是nonce重复；仅在数据库中贴不同租户标签不会改变密码输入。
2. 可使用真正独立的数据密钥，或经证明的全局分配/命名空间，确保完整nonce字节在同密钥下唯一；同时考虑重启和迁移。
3. 将租户等上下文绑定AAD并执行服务端授权，测试跨租户替换、同时写入、恢复及密钥版本错误。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：以业务命名空间代替密码机制的真实作用域。

### 3. 被替换公钥（10分）

**题意与考点**：攻击者只能改下载网页，不能改客户端预置可信根；网页提供发行包、公钥与签名。解释哪些验证仍不足，并提出安全链。

考点：PKI/可信渠道。

**参考答案与防御思路**：

1. 包、公钥、签名一起可被替换，数学签名正确只能证明所提供私钥签了当前包，不说明它属于发行者。
2. 客户端从独立可信策略验证发行身份、公钥链、用途和项目，不能自动信任网页新根或新公钥。
3. 签名元数据绑定版本与渠道，并执行反回滚；验收替换公钥、错误项目和旧签名均被拒绝。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：认为验签成功无需问公钥从哪里获得。

### 4. 签名随机数治理（10分）

**题意与考点**：团队自制ECDSA接口，只在开发机测了一次正常签名。无需给出攻击推导，说明随机数与实现评审应覆盖哪些风险。

考点：ECDSA/实现安全。

**参考答案与防御思路**：

1. 签名中的每消息秘密值必须按标准安全产生；重复、偏差或泄露可严重危及私钥，不可使用普通伪随机或随意计数。
2. 采用成熟符合标准的实现，可按标准使用适当确定性生成方式，审查参数、公钥验证、错误处理与侧信道防护。
3. 验证并发、重启、随机源异常和日志不泄露秘密；禁用自制接口并独立复核，不能用“签名能验过”证明安全。

**评分要点**：按上述3项分别给3、3、4分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把功能正确当作密码实现安全，或自行设计确定性公式。

### 5. 口令数据库泄露（15分）

**题意与考点**：泄露内容包含旧MD5、带盐SHA-256和现代Argon2id记录；另有独立pepper仍未发现泄露。设计风险分层和迁移，不进行猜测或破解。

考点：口令泄露/迁移。

**参考答案与防御思路**：

1. 先确认泄露范围、参数、盐与pepper保护状态，保全证据并隔离异常访问；没有观察到pepper泄露不等于证明未泄露。
2. 对快速哈希及高风险账号优先强制重置和会话撤销，通知受影响使用者避免复用，并启用抗钓鱼MFA。
3. 使用适当调优的专用慢哈希与独立盐，成功验证后升级或要求重置，停用仍长期留存的弱旧记录。
4. 管理pepper轮换与恢复方案、独立服务权限和审计，评估认证容量并限制在线并发。
5. 验收无明文落日志、弱版本退役、旧会话失效与恢复可用；报告剩余风险，不承诺哈希让泄露无影响。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：只新增pepper后继续保留弱口令与弱哈希，或忽视泄露记录可能已被离线复制。

### 6. 主密钥轮换与泄露（15分）

**题意与考点**：对象采用随机数据密钥加密，主密钥包装数据密钥。主密钥泄露后，仅重新包装数据密钥是否足以恢复历史机密性？

考点：信封加密/历史暴露。

**参考答案与防御思路**：

1. 计划性轮换可通过重新包装降低大对象重写成本，但已泄露主密钥可解开攻击者留存的旧包装密钥。
2. 仅重包装不改变数据密钥，不能撤回对方已知的数据密钥或明文，应评估旧密文和备份副本。
3. 按事件风险生成新数据密钥并重加密所需对象，替换主密钥、撤销权限与消除泄露来源，同时治理旧副本。
4. 保留版本映射和恢复程序，验证新写、旧读、重加密完整性及授权，不为追求速度无限保留旧解密权限。
5. 明确哪些历史暴露不可逆，以受影响数据、密钥调用与时段为证据沟通风险。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把运维轮换步骤当作泄露后的完整机密性修复。

### 7. 先使用再验签（15分）

**题意与考点**：流式更新器边下载边运行内容，最后才核对签名；团队认为失败可回滚。评估时序并提出替代。

考点：验证前副作用。

**参考答案与防御思路**：

1. 最终验签无法撤销已执行的任意副作用，回滚不等于未认证内容从未被使用。
2. 先下载到受限暂存区，验证完整签名及项目、版本、渠道与时间策略，再执行受控安装。
3. 大文件流式验证可使用经过设计的签名清单和分块结构，但每块使用必须建立所需信任，不能自制摘要链后跳过发行策略。
4. 暂存区限制执行与权限，安装采用最小权限、可恢复事务和审计，错误路径保持失败关闭。
5. 用被修改、缺块、错误签名、错项目与中断样本验收“无副作用拒绝”，并检查日志与缓存不会提前激活。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：把后验校验当成先验授权，或以最终可恢复掩盖已发生泄露。

### 8. 长期档案算法迁移（15分）

**题意与考点**：机构需保密保存档案20年，系统含传统RSA/ECC及旧格式。提出不依赖“马上更换所有算法”的迁移方案。

考点：密码敏捷性/寿命。

**参考答案与防御思路**：

1. 盘点算法、密钥、协议、证书、格式、客户端与供应商依赖，标注数据保密寿命及历史副本暴露风险。
2. 关注适用的后量子标准与维护实现，区分加密/协商、签名和数据存储职责，选择可审计迁移目标。
3. 设计带版本的格式、密钥用途隔离与受控兼容，按风险分批迁移，防止静默降级为旧算法。
4. 验证性能、互通、备份恢复、撤销与权限，记录支持矩阵及退役条件。
5. 已被留存的旧密文无法通过未来换算法收回；报告剩余风险并持续复核长期敏感数据。

**评分要点**：按上述5项分别给3、3、3、3、3分；每项需要说清机制或可检验证据，部分正确可酌情给分。

**易错点 / 踩坑点**：以“ECC密钥短且现代”忽略长期量子风险，或仅换服务端算法不改客户端和格式。
