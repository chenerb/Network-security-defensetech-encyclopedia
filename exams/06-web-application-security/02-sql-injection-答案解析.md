## 逐题解析

### 1. 参数化查询最直接保证什么？

**正确答案：D。**

- **A（所有用户只能读自己数据）**：对象授权还需单独检查。
- **B（数据库不可停机）**：可用性需要容量和限额。
- **C（输入永远格式正确）**：参数化不自动验证业务格式。
- **D（值不改变预先定义的 SQL 结构）**：结构和值分离，正确。

**考点**：参数化边界。

**易错点／踩坑提示**：把语法安全当作业务授权。

### 2. 报表需要选择排序列，最稳妥的做法是？

**正确答案：B。**

- **A（把任意表名作为值参数）**：标识符通常不能作为普通值绑定。
- **B（将选择映射到固定列名白名单，值另行绑定）**：结构选择有限可控，正确。
- **C（仅删除空格）**：字符过滤不证明结构安全。
- **D（拼接前做 Base64 编码）**：编码可逆，不构成 SQL 防线。

**考点**：动态标识符。

**易错点／踩坑提示**：为列名使用普通占位符。

### 3. 使用 ORM 后，仍重点审核哪处？

**正确答案：A。**

- **A（原生查询与动态字符串接口）**：这些接口可能绕开参数绑定，正确。
- **B（静态页面颜色）**：不决定数据库查询边界。
- **C（只看文件扩展名）**：扩展名不证明调用方式。
- **D（不需要再审核）**：框架不提供全面免疫。

**考点**：ORM 边界。

**易错点／踩坑提示**：以工具名称代替代码证据。

### 4. 存储过程内部拼接不可信文本，应如何判断？

**正确答案：C。**

- **A（只要在数据库内就安全）**：运行位置不改变字符串拼接风险。
- **B（只有 GET 才有风险）**：输入通道不是根因。
- **C（仍可能注入，需要绑定或有限结构映射）**：结构与数据仍必须分离，正确。
- **D（提高账号权限即可）**：高权限扩大损害。

**考点**：存储过程。

**易错点／踩坑提示**：把所有存储过程视为天然安全。

### 5. 应用只需要读订单和更新状态，数据库账号应？

**正确答案：D。**

- **A（拥有实例管理员权限）**：多余管理能力扩大影响。
- **B（共享运维 root）**：共享账号破坏追责和最小权限。
- **C（能访问所有测试和生产库）**：环境横向访问无必要。
- **D（仅获必要对象与操作权限，环境分离）**：限制影响范围，正确。

**考点**：数据库最小权限。

**易错点／踩坑提示**：把注入风险完全寄托于输入处理。

### 6. 为何过滤引号与参数化不同？

**参考答案与解析**：过滤试图猜测哪些字符危险，容易误伤合法姓名，且会受数据库语法和上下文影响；参数化由驱动将值独立传递，输入不会成为语句结构。格式、长度和业务范围验证仍有价值，但不是解释器边界的替代。

**评分要点**：关键概念及边界 5 分；因果解释或防御步骤 5 分；验证证据和条件 5 分。

**考点**：过滤与结构分离。

**易错点／踩坑提示**：把“没有引号”误当作不可注入证明。

### 7. 查询已参数化，用户输入别人的订单 ID 后仍能读到订单。应修什么？

**参考答案与解析**：修复对象级授权：服务端从可信身份获得租户或用户信息，确认目标订单在允许范围内，再返回最少字段。参数化继续保留；用虚构账号覆盖自己的订单成功、他人订单拒绝与管理员例外。

**评分要点**：关键概念及边界 5 分；因果解释或防御步骤 5 分；验证证据和条件 5 分。

**考点**：注入与授权区别。

**易错点／踩坑提示**：再次增加字符过滤而不检查归属。

### 8. 场景：动态报表允许选择列和日期，团队用字符串拼接，并以管理员账号查询。提出修复和验收。

**参考答案与解析**：日期等值使用驱动绑定并验证格式范围；列和排序方向通过固定映射选择，不接受任意 SQL 片段；审核报表和存储过程原生接口；改用仅能读所需视图的独立账号，限制导出与查询资源；授权测试覆盖所有合法选择、未知列拒绝、边界日期、跨租户拒绝和统一错误，检查数据库细节不被回显。

**评分要点**：值绑定 10 分；标识符映射 10 分；权限和限额 8 分；错误及回归验收 12 分。等价方案按保护目标、可操作性和证据给分。

**考点**：报表结构与权限。

**易错点／踩坑提示**：只加 WAF 而保留危险构造。
