# 单点登录与零信任：统一身份之后仍须逐次授权

## 概述

一次登录可以访问多个系统，是否意味着登录后应永远信任？单点登录（Single Sign-On，SSO）让多个依赖方复用可信身份提供者的认证；零信任（Zero Trust）要求依据资源、身份和上下文做显式决策。前者减少重复登录，后者约束每次访问，二者可以协同。

> **教育与防御边界**：本篇仅用于教育学习与合法防御，不提供令牌窃取或攻击代码。

## 历史背景

企业联合身份先广泛使用 SAML，移动与 Web 生态发展出 OAuth 2.0 和 OpenID Connect（OIDC）。NIST SP 800-207 于 2020 年给出零信任架构框架，强调保护资源而非把网络位置当作可信依据。它不是单一设备，也不意味着每次鼠标点击都让用户输入密码。

## 核心原理

身份提供者（Identity Provider，IdP）认证用户，依赖方（Relying Party，RP）验证身份断言。OIDC 是建立在 OAuth 2.0 上的身份层；OAuth 主要处理委托授权，单有 access token 不能随意当作登录身份凭证。ID token 表达给特定客户端的认证结果，access token 用于特定资源访问，两种令牌的接收者与验证规则不同。

验证令牌不能仅“能解码 JWT”：应限定可信签发者、受众、算法、有效期及所需的 nonce 等关联状态。使用授权码流程与 PKCE，严格注册重定向地址，防止把结果交给错误回调。签名保护完整性，JWT 的常见编码不隐藏载荷，不能放入不必要的秘密。

零信任架构包含策略决策与执行：结合用户或工作负载身份、设备状况、资源敏感度等信号，授予范围受限的访问，并在风险变化、会话超时或高风险操作时重新评估。设备健康信号也会过期或被伪造，必须治理其来源。SSO 集中了账号管理，也集中故障与攻击影响；IdP 失陷可影响多个系统，需要强认证、隔离管理、高可用和令牌撤销策略。

> **🧠 费曼自问**：总前台验过身份后，为什么每间办公室仍要核对访问目的？

## 通俗解释

SSO 像一个可靠总前台发给访客通行证明，各办公室不重复办证；零信任像每个办公室依据证明、设备和任务决定是否开门。证明有接收单位、有效期和用途，不能拿给任意地方无限使用。

## 📖 寓言故事

园区给访客发一张总通行证，大家不用在每栋楼重新登记。保安一度认为能进园区的人都可信，结果来送花的人也进入了财务室。园区于是让各楼查明访客要见谁、证件是否有效和包裹是否符合要求。后来总前台停电，财务室拒绝新授权，普通展厅按预先规定短暂接受已有低风险预约，并记录每次使用。停电结束后，他们统一核销临时许可。方便的统一登记必须配合每处门锁的有限授权，前台故障时的应急规则也必须提前定义。

## 防御步骤 / 工作流程

1. 盘点应用、服务账号和身份提供者，清理共享账号，设置管理员抗钓鱼 MFA 与独立管理权限。
2. 选择维护良好的 OIDC/SAML 实现，固定签发者、接收者和回调，使用适合客户端的安全流程。
3. 验证令牌与协议关联状态，建立本地受控会话；在 API 端再做对象及动作授权。
4. 用策略执行点限制资源范围与期限，接入可信设备信号，关键交易触发再认证。
5. 演练 IdP 故障、签名密钥轮换和员工离职，明确令牌、缓存与各系统会话的撤销时限。

## 优缺点分析

SSO 改善体验、便于集中禁用账号，零信任缩小过度信任范围。代价是身份服务成为关键依赖，策略集成和终端治理复杂；频繁错误拦截会诱发绕过，应以业务成功率与风险共同评估。

## 应用场景

企业 SaaS 联合登录、远程办公、云上工作负载与第三方临时协作都适用。网络隔离、VPN 和防火墙仍有价值，它们提供额外边界，但不能代替资源授权。

## 实践建议

把账号禁用、access token 有效期、本地会话撤销和授权缓存更新分开测量。不要声称部署一款网关就完成零信任；先从敏感资源与高权限身份开始，逐步验证策略命中、误阻与恢复流程。
