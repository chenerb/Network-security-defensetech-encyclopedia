# 防火墙与网络隔离：明确哪些流量有理由通过

## 概述

公司装了防火墙，为什么内部服务仍能互相失控访问？防火墙（Firewall）按规则允许或拒绝网络流量；网络隔离（Network Segmentation）把资产划入不同信任区域，并在跨区路径上执行约束。只有边界设备、没有内部规则，无法限制横向影响。

> **教育与防御边界**：本篇仅用于教育学习与合法防御，不提供绕过或攻击代码。

## 历史背景

早期包过滤主要匹配地址、端口与协议，后来发展出状态检测、代理和应用感知能力。NIST SP 800-41 Rev.1 于 2009 年讨论防火墙策略治理，仍可用于理解基础流程，但具体云平台、容器和现代产品能力应查对应文档，不能把旧指南当作今天全部产品功能清单。

## 核心原理

无状态过滤分别判断数据包；状态检测（Stateful Inspection）跟踪连接状态，允许与已授权连接对应的返回流量。它不等于检查应用操作是否安全：一个允许的 HTTPS 连接中仍可能包含越权请求。规则顺序、默认动作和不同链路的执行位置决定实际结果。

隔离把互联网入口、应用、数据库、管理和备份等区域分开。跨区规则应写清来源、目标、协议、业务目的与所有者；微分段（Microsegmentation）进一步在工作负载间限制通信。VLAN 只是组织二层广播域的手段，若跨 VLAN 路由不受控制，就没有形成完整安全边界。网络地址转换（NAT）也不等于访问控制策略。

入站限制减少暴露面，出站限制控制不必要外联；身份和应用层授权则补足 IP 地址无法表达的语义。IPv6、云安全组、主机防火墙和容器网络都可能成为另一条路径，需要统一盘点。默认拒绝必须配合可靠 DNS、时间同步、更新等必要依赖，否则业务会推动管理员添加过宽“临时”规则。

> **🧠 费曼自问**：把楼层分开之后，如果所有楼梯都敞开，隔离还剩多少意义？

## 通俗解释

防火墙像按来访名单查入口的门卫，网络分区像把仓库、办公室和财务室分开。门卫会认出“刚出去的人正在回来”，类似连接状态；但他无法只凭大门通行证判断财务审批是否合法。

## 📖 寓言故事

学校在大门安排了保安，却把实验室和成绩室的门都敞开。一个持访客证的人进校后误入成绩室，老师才发现大门名单不足以保护内部房间。学校给每个房间建立访问表，采购人员只能到仓库，实验室只能向指定设备取数。为赶工临时开放了一条全楼通道，后来无人关闭。管理员改为让每张临时通行条注明到期日，并在晚间核对门锁记录。隔离不是画出几块区域，而是控制每条连接区域的路，并持续清理例外。

## 防御步骤 / 工作流程

1. 盘点资产、管理入口和真实通信依赖，画出信任区及所有跨区路径，包括 IPv6 与云网络。
2. 用默认拒绝策略逐项放行必要流量，标明来源、目标、端口、目的、所有者和失效日期。
3. 把数据库、备份和管理面置于受控区域，限制东西向与出站访问，避免以整个内网为可信来源。
4. 在测试环境检查规则顺序、返回流量与业务依赖；灰度部署，准备可审计回滚。
5. 结合拒绝日志、流量统计与业务反馈定期复核，删除失效规则，监控配置变更。

## 优缺点分析

网络约束可在应用漏洞出现时缩小可达范围，便于分区治理。代价是规则膨胀、动态地址与多执行点增加维护成本；加密流量和被允许连接的恶意行为，需要应用安全及检测能力补充。

## 应用场景

互联网入口使用受控服务区，应用仅访问必要数据库端口；运维通过受管入口到指定主机；备份区限制普通终端写入。对云资产应从业务依赖出发，而不是照抄一套传统边界拓扑。

## 实践建议

审查“任意来源到任意目标”规则与多年未命中的例外，但删除前确认罕见维护任务。日志不宜无上限逐包记录，应按风险采样和聚合。每次上线证明必要连接可用、非必要连接被拒绝，不能只确认网页能打开。

## 🧠 费曼自测

1. 状态检测为什么不是业务授权？
2. VLAN 与真正安全隔离差在哪一步？
3. NAT 为什么不能代替明确的防火墙规则？
4. 默认拒绝上线前应识别哪些公共依赖？

## 总结

防火墙与隔离限制“能到哪里”，应用授权限制“到了以后能做什么”。规则必须有目的、生命周期和验证证据。
