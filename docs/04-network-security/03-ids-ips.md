# IDS 与 IPS：从发现异常到审慎阻断

## 概述

告警越多，网络是否越安全？入侵检测系统（Intrusion Detection System，IDS）观察并告警；入侵防御系统（Intrusion Prevention System，IPS）可以在流量路径中阻断。发现异常、判断危害与执行阻断是不同环节，没有人处理的海量告警并不会自动形成防御。

> **教育与防御边界**：本篇仅用于教育学习与合法防御，不提供规避检测或攻击代码。

## 历史背景

入侵检测从审计日志分析发展到网络、主机与行为分析。NIST SP 800-94 于 2007 年总结 IDPS 基础分类；官方页面明确 2012 年 Rev.1 草案没有成为正式版且已撤回，因此本篇不称其为最新产品指南。加密与云网络发展后，终端、身份和应用日志成为重要补充。

## 核心原理

基于特征（Signature-based）的检测匹配已知模式，较易解释却可能漏掉未知行为；异常检测（Anomaly-based）比较基线偏差，能发现新变化，也容易把业务更新当作威胁。协议分析检查语义与状态，需要正确解析、重组和上下文。没有一种方法保证发现所有攻击。

旁路 IDS 常通过镜像或流量采集观察，不会天然阻断；采集端丢包、镜像覆盖不全或时间不一致，会制造盲区。内联 IPS 能阻断，但规则误判、性能耗尽或设备故障也可能中断正常业务，需明确故障放行（Fail-open）还是故障拒绝（Fail-closed），并配置高可用与告警。

精确率表示告警中真正相关事件的比例，召回率表示目标事件被发现的比例；都依赖标注与范围，不能只凭告警数量推断。加密网络流量通常暴露连接元数据，无法任意检查 TLS 内部内容。受控解密涉及证书信任、隐私与性能权衡，可优先结合应用日志、终端行为和身份事件，构成更完整的证据链。

> **🧠 费曼自问**：报警器和自动关门器为什么不能使用完全相同的容错标准？

## 通俗解释

IDS 像观察异常动静后打电话的保安，IPS 像还会按规则关闭门的保安。越有权影响业务，越需要准确证据、操作记录和恢复能力；把“陌生声音”直接等同“入侵”容易把客人挡在外面。

## 📖 寓言故事

博物馆安装了能听声音的警铃，闭馆时很有效。新展厅开幕后，空调和游客的声音让警铃不停响，保安逐渐不再接听。馆长一度让所有铃声都自动锁门，结果参观团被困在大厅。后来团队记录营业时段与设备基线，把高可信入侵迹象交给自动门锁，其他异常先由值班人员核实；门锁失灵时有演练过的替代守卫。能发声不是能防守，只有合理阈值、责任人和受控响应，才让警铃重新有用。

## 防御步骤 / 工作流程

1. 根据资产和威胁确定监测目标，安排互联网入口、关键跨区路径与主机日志覆盖。
2. 测量采集丢包、时间同步与性能，保护规则、管理接口和日志访问权限。
3. 用授权的合成事件验证规则，先观察再灰度阻断，分别评估漏报、误报和业务影响。
4. 为告警设置分级、去重、关联与责任人，把高可信事件连接到有回滚的响应流程。
5. 演练设备故障、流量峰值与规则误阻，记录恢复时间并定期更新业务基线。

## 优缺点分析

检测能补足静态访问规则，IPS 可在确认威胁时缩短响应时间。代价是持续调优、证据分析与运维投入；盲区、加密和未知行为限制覆盖，不能用“已部署”代替效果测量。

## 应用场景

边界监测发现异常连接，内部跨区监测发现异常访问，主机日志帮助判断进程与账号行为。对于可用性关键业务，可先旁路观察，再对有限规则采用阻断，避免一次性把所有告警自动处置。

## 实践建议

对每条高优先级规则说明触发证据、覆盖范围、误报来源和下一步调查。复核告警处理时间与未覆盖资产，不只统计每天告警数。若无法看到载荷，应明确写出能力限制，而不是默默宣称仍检查了全部内容。

## 🧠 费曼自测

1. IDS 看到事件后为什么不一定阻断？
2. 异常检测为什么可能误报业务更新？
3. TLS 加密后可以从哪些其他来源补充证据？
4. 如何决定 IPS 故障时放行还是拒绝？

## 总结

检测需要覆盖与证据，阻断需要把风险和可用性一起评估。规则效果必须通过可复核数据和演练来说明。
