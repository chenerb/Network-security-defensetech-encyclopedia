# 数据库安全与脱敏

> **学习范围**：本文仅用于教育学习与授权防御；威胁背景服务于防御设计。

## 概述

给手机号打上星号，是否就能把整张用户表放心交给任何人？数据库安全保护访问与数据状态；脱敏（Data Masking）降低展示或复制中暴露的信息量。两者相关，但一个界面看不到完整字段，不等于底层数据已失去识别能力。

## 历史背景

关系数据库发展出用户权限、事务和审计机制。数据分析、运维和开发测试的普及，使“复制生产库”成为常见风险，推动了视图、行级安全、令牌化和测试数据生成。现代数据库保护还必须覆盖云控制台、快照、备份与凭据交付。

## 核心原理

数据库账号应按服务与环境分离，只能连接必要数据库、执行必要操作。表、列、视图和行级策略可以进一步限制数据范围；不同产品的策略绕过条件、管理员行为和连接池上下文不同，应按照当前官方文档验证。应用层逐对象授权仍需存在，不能假设数据库会自动理解业务用户。

透明数据加密（Transparent Data Encryption，TDE）保护磁盘文件等静态数据，数据库运行时仍会向获授权的查询返回明文。字段级加密把部分保护放到更细边界，但影响检索、排序与索引；密钥、解密服务和应用权限的安排决定真实效果。

动态脱敏在查询或界面返回时改变展示，适合降低客服等角色的直接暴露；底层值仍在，宽权限查询、推断或导出可能绕过展示限制。静态脱敏生成另一个数据集，适合测试，但必须处理姓名、自由文本、时间地点等关联字段，并检查分布与业务约束。

令牌化（Tokenization）用替代标识代替原始值，映射库需独立保护。假名化（Pseudonymization）仍可能通过额外信息关联到个人；匿名化（Anonymization）需要考虑可合理获得的辅助信息与重识别风险，不能仅因为删除姓名就宣布完成。

> 🧠 费曼自问：给姓名换代号，与再也无法识别那个人，为什么不是同一件事？

## 通俗解释

数据库像医院档案室：门锁是访问控制，档案柜加密是介质保护，窗口遮住部分字段是动态脱敏，另做一套教学病例是静态脱敏。护士拿到柜子的总钥匙时，窗口遮挡就不再足够。

## 📖 寓言故事

档案室为实习生准备病例，把每个人的姓名换成代号，却保留了精确生日、住址和罕见病记录。实习生发现同学的生日与住址都在表里，很快认出了他。主任起初责怪代号太短，准备换更长的编号。档案员却指出，问题不在编号长度，而在留下的线索太独特。于是教学表改用年龄段、较粗地区和合成病例，对敏感诊断限制访问，并由独立人员检查可能的关联。原始档案仍放在另一个权限域，代号映射也单独保管。寓意是：遮住直接标识只是起点，辅助字段、映射权限与接收环境共同决定暴露和重识别风险。

## 防御步骤

1. 收敛数据库网络入口，管理工具必须认证并限制来源，客户端验证加密连接的证书。
2. 服务账号按环境分离，取消实例管理与不必要数据导出权限，定期复核账号。
3. 分类敏感字段，按威胁选择静态或字段加密，把密钥与数据库权限分开治理。
4. 为展示和测试分别选择脱敏方案，优先合成数据，检查关联字段及重识别风险。
5. 审计异常批量读取、权限变更和快照导出；验证备份恢复、凭据轮换及脱敏访问路径。

## 优缺点分析

行列级限制能缩小暴露，策略配置与性能需要验证；TDE 对应用透明，但不能阻止合法账号滥用；脱敏提高数据可用性，却可能保留关联信息。字段加密保护更细，但检索需求和密钥可用性带来成本。

## 应用场景

客服界面可显示必要的局部号码；测试环境优先合成或经评估的静态脱敏数据；科研共享要进一步评估发布模式、辅助信息与接收方能力，而不是直接发布客服视图。

## 实践建议

不要记录完整敏感查询参数或凭据。用不同角色、不同租户和连接池复用场景验证拒绝路径；审计数据库之外的快照和云控制台。脱敏效果要从接收者能取得的信息出发测试。

## 🧠 费曼自测

1. 为什么启用 TDE 后管理员仍可能读到明文？
2. 动态与静态脱敏分别改变什么？
3. 为什么删除姓名不足以实现匿名化？
4. 令牌映射库失陷会带来什么影响？

## 总结

保护数据库需要网络、身份、细粒度权限、加密、审计和恢复协同。脱敏方案必须匹配使用场景，明确定义残余识别能力。
