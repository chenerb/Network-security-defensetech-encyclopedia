# 隐私保护技术：从去标识到差分隐私

> **学习范围**：本文仅用于教育学习与授权防御；威胁背景服务于防御设计。

## 概述

没有姓名的统计表，为什么仍可能让人识别某位居民？隐私保护技术（Privacy-Enhancing Technologies，PETs）减少数据处理给个人带来的风险。先说明要保护谁、对手能看到什么、希望得到什么结果，再选择技术，不能凭“匿名”或“加密”标签判断。

## 历史背景

去标识技术从删除直接标识，逐步关注准标识符与外部数据关联。2000 年代差分隐私形成数学框架，以相邻数据集输出分布的接近程度描述隐私保障。NIST 在 2023 年发布 SP 800-188，2025 年发布 SP 800-226，强调技术保障和治理条件都要评估。

## 核心原理

假名化仍保留重新关联的可能，需要隔离映射和限制辅助信息。匿名化并非简单删除字段；年龄、地区、职业等准标识符组合可能唯一。k-匿名使每种准标识组合至少对应 k 条记录，却不能一般地阻止敏感属性同质性推断或辅助信息推断。

差分隐私（Differential Privacy，DP）比较只相差一个受保护单位的数据集。若对任意相邻数据集 D、D′ 和任意输出事件 S，随机机制 M 都满足下式，则称为 (ε, δ)-DP：

$$
P[M(D)\in S]\le e^{\varepsilon}P[M(D')\in S]+\delta
$$

必须明确相邻关系：保护一个人的一条记录，和保护一个人的全部记录不同。ε 控制分布可区分程度，通常越小约束越强，可能需要更多噪声；δ 是定义中的加性松弛项，不宜直接解释成“个人泄露概率”。ε 也不是百分比，不能脱离机制、δ、单位和预算单独比较。

同一人的数据被多次使用会组合消耗预算。基本顺序组合将各次 ε 与 δ 相加；更紧的会计方法需要明确条件。真正互不重叠的受保护单位可满足并行组合条件，重复查询同一群体不能伪称并行。只对已发布 DP 输出做后处理不额外消耗预算，但再次访问原始数据会改变判断。

安全多方计算（MPC）与同态加密（Homomorphic Encryption）让部分计算在不暴露输入或密文状态下进行，仍需说明参与方串通、密钥和泄漏模型；结果本身仍可能泄露个人信息。联邦学习（Federated Learning）不集中原始数据，但梯度等更新可能泄露，需要安全聚合、访问控制或 DP 等额外措施。

## 通俗解释

去标识像遮住名单的名字；差分隐私像让统计结果对某个人是否加入不太敏感；密码计算像允许大家共同算账却不直接交换账本。它们保护的是不同观察位置。

## 📖 寓言故事

村委会公布居民健康统计，只删去了姓名，却保留每户位置和年龄。大家从唯一一位高龄住户的描述认出了他。会计于是提出，只发布带适当扰动的总数，让一个人的加入不明显改变统计结果。第一次发布很谨慎，后来各部门反复索取略有不同的统计，会计发现这些结果能一起提供更多线索。他建立预算账本，限制重复请求，并把已经发布的结果加工成图表，避免再查原表。另一位村干部说把原表加密就够了，会计提醒：锁住账本管住输入，公开结果仍要管住。寓意是：隐私承诺要明确保护单位、可见输出与组合使用条件，不能靠单一标签保证。

## 防御步骤

1. 明确数据处理目的、保护单位、接收方、辅助信息和可接受风险。
2. 优先减少数据、限制访问与发布范围，再选择去标识、DP 或密码计算。
3. DP 项目定义相邻关系、贡献上限、敏感度、机制、ε/δ 和发布预算，避免用自制噪声冒充保障。
4. 管理跨团队查询与组合会计，检查中间日志、调试输出及异常路径是否绕过机制。
5. 用效用评估和隐私审核共同决定发布，记录适用条件与残余风险，持续监测环境变化。

## 优缺点分析

DP 给出可解释的数学约束，却会损失精度且实现容易踩坑；密码计算限制输入暴露，带来计算与通信成本；去标识较直观，但受辅助信息影响。没有一种技术自动解决目的、同意、访问和保留问题。

## 应用场景

公共统计适合评估 DP 与受控发布；跨机构协作可评估 MPC；训练流程可组合联邦学习、安全聚合与 DP。稀有疾病或小群体统计尤其需要谨慎评估效用与输出暴露。

## 实践建议

先用虚构数据编写威胁模型和预算账本，不在教学中自行认证一个机制为 DP。区分经验重识别测试与数学保证：一次测试没识别成功，不等于不存在风险。

## 总结

隐私保护要精确描述单位、观察面、机制和组合条件。减少数据与治理流程是基础，技术保证则需要按其真实假设使用和验证。
