# AI 安全红队与评估

## 概述

测试一百次没有泄密，能宣布模型安全吗？AI 红队（AI Red Teaming）寻找系统在明确威胁条件下的失效路径；安全评估（Security Evaluation）用固定规则测量风险与正常任务表现。前者擅长探索，后者帮助比较与回归，两者要一起使用。

> 所有评估仅用于教育学习与合法防御，须明确授权范围，使用合成秘密与隔离工具，不测试无许可的外部系统。

## 历史背景

传统红队验证基础设施和响应，AI 系统增加了数据、模型行为、检索与工具链风险。[NIST AI RMF 1.0](https://www.nist.gov/itl/ai-risk-management-framework) 与 [AI 600-1](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence) 提供风险管理与测量思路；[MITRE ATLAS](https://github.com/mitre-atlas/atlas-data) 汇集面向 AI 的威胁行为和案例，可帮助组织场景。知识库映射帮助覆盖讨论，不是风险已解决的证明。

## 核心原理

先定义攻击者能控制什么、知道什么、尝试多少次，成功意味着什么。模型说出不安全建议、发起工具请求、执行器实际越权、业务受损，应分别标记。把模型拒绝率当作安全总分，会漏掉过度拒绝和后端漏洞。

| 指标 | 清楚的分母 | 使用限制 |
|---|---|---|
| 场景成功率 | 预先定义的有效场景数 | 明确“一次成功”与重试预算 |
| 单次尝试成功率 | 有效尝试次数 | 重复输入不等于独立场景 |
| 泄露率 | 包含授权合成秘密的有效测试 | 分清提示回显与受保护数据 |
| 正常任务完成率 | 独立正常任务集 | 检查答案质量与副作用 |
| 误拒绝率 | 应当允许的正常请求 | 拒绝不总是安全收益 |

例如 100 个场景各重试 5 次，10 个场景至少成功一次、合计 12 次成功：按场景是 10/100，按尝试是 12/500。不能任选较好看的分母；未完成、超时、工具故障与无效输入按预先规则分类，并披露数量，不得默默删除失败运行。

> 🧠 **费曼自问**：五百次尝试和一百种场景，为什么不是同一个样本数？

## 通俗解释

评估像检查雨伞：先规定雨量、风向和持续时间，再看是否漏水。只在晴天撑一百次没有漏水，说明不了暴雨中的表现；也不能把不让人出门当成雨伞性能提高。

## 📖 寓言故事

制伞匠带来十把伞，每把在同一滴水下试十次，宣布“一百次零漏水”。检验员换了风向，其中两把开始漏水。学徒想把这两次称为“异常天气”删掉，检验员让他先写明试验范围和作废条件。后来他们固定雨量、风速与时长，保留正常开合的检查，用新的一组天气复测修补后的伞。报告还写出没有测试的风速。多试几次能发现随机问题，却不能替代场景覆盖；失败是否算数，要在看见结果之前约定。

## 防御步骤 / 工作流程

1. 明确授权者、系统范围、数据、工具副作用、预算、停止条件和发现后的报告路径。
2. 建立场景矩阵，覆盖直接与间接注入、检索权限、供应链、污染、工具授权和资源消耗，并加入正常任务。
3. 固定模型、提示、检索库、工具与策略版本，记录采样设置；按风险确定重复次数，不宣称完全确定。
4. 预定义成功标准、分母与异常处理，使用合成秘密和模拟执行器；重要结论以真实受控执行证据验证。
5. 自动判分与人工复核结合，检查裁判偏差；按场景、严重度和前提报告结果，同时保留未测范围与不确定性。
6. 将探索发现整理成回归样例，修复后在保留集和正常任务上复测；上线持续监测，版本变化时重新评估。

## 优缺点分析

### 优点

能发现单元测试未覆盖的链路失效，回归集支持版本比较，双重指标帮助避免“全部拒绝”的虚假进步。

### 缺点

样本与裁判都有偏差，有限测试无法证明绝对安全。公开基准可能污染训练，探索样例过度用于调参会失去独立性。

## 应用场景

模型换版、RAG 知识库更新、新增高影响工具、扩大租户范围时，都应检查原有控制是否仍成立。

## 实践建议

报告写清“在何种配置与预算下测了什么、多少有效样本、哪些失败和未测条件”。即使 100 个独立场景零失败，也只能描述该样本表现；真实场景相关性会进一步限制统计外推。演练结束撤销测试权限并按约定处理日志。

## 🧠 费曼自测

1. 探索红队和固定评估集各有什么用途？
2. 为什么必须在测试前确定成功条件与分母？
3. “拒绝率提高”可能损害哪个指标？
4. 模型输出与实际工具动作为什么需要分开判分？

## 总结

评估是有边界的证据，不是安全保证。授权、有效分母、版本、正常任务与实际动作共同决定一个结果能解释什么。
