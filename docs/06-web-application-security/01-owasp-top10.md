# OWASP Top 10 总览：把风险分类变成工程行动

> **学习范围**：本文仅用于教育学习与授权防御；威胁背景服务于防御设计。

## 概述

背熟十种风险，就能证明网站安全了吗？OWASP Top 10 是面向开发者的风险认知文档，用于建立共同语言；完整的安全要求、测试与运营仍需要威胁模型和验证标准。本篇以官网核验的 **2025 版**为依据。

## 历史背景

OWASP 长期通过社区与数据整理 Web 风险。2021 版仍有历史学习价值，但 2025 版调整了排序与分类，新增“软件供应链失败”和“异常条件处理不当”等关注点。版本变化说明工程环境在变化，并不代表排到后面的风险可以忽略。

## 核心原理

| 2025 类别 | 中文说明 | 可执行的防御方向 |
|---|---|---|
| A01 Broken Access Control | 访问控制失效 | 服务端逐对象授权、默认拒绝 |
| A02 Security Misconfiguration | 安全配置错误 | 配置基线、关闭无用功能、核验部署 |
| A03 Software Supply Chain Failures | 软件供应链失败 | 依赖来源、构建身份、更新与供应商治理 |
| A04 Cryptographic Failures | 密码学失效 | 成熟算法、密钥管理、敏感数据保护 |
| A05 Injection | 注入 | 参数化查询、安全 API、上下文处理 |
| A06 Insecure Design | 不安全设计 | 滥用场景、业务约束、信任边界 |
| A07 Authentication Failures | 身份认证失效 | MFA、会话管理、恢复流程保护 |
| A08 Software or Data Integrity Failures | 软件或数据完整性失效 | 来源验证、签名、受信更新和数据处理 |
| A09 Security Logging and Alerting Failures | 安全日志与告警失效 | 可关联日志、检测规则、响应验证 |
| A10 Mishandling of Exceptional Conditions | 异常条件处理不当 | 安全失败、回滚、资源限制、错误保护 |

列表是风险类别，不是十个互斥漏洞。一次事件可能同时涉及配置、授权与日志失效。供应链治理关心组件、服务与构建过程的系统风险；完整性控制关心软件或数据能否被未经授权地改变，两者重叠但不等同。

风险优先级还要看资产价值、暴露面、可利用条件与现有控制。网站没有 SQL，并不免于其他注入；用了 HTTPS，也仍需对象级授权。实施时把类别转成“负责人、控制、测试、证据”，可借 OWASP ASVS 5.0.0 的具体要求细化验证。

> 🧠 费曼自问：排行榜为什么不能代替你家房屋的消防检查单？

## 通俗解释

Top 10 像体检中的常见病提醒；威胁模型确定你个人的危险因素，ASVS 等要求把提醒细化为检查项。记住病名和做完检查是不同阶段。

## 📖 寓言故事

小镇发布了十种常见火灾原因。旅店老板把名单背得滚瓜烂熟，还给每间客房贴了一张。检查员来时却发现，后门被杂物堵住，夜班员工不知道警报响后该通知谁。老板辩解说自己已经“学习了十项风险”。检查员让他画出旅客、厨房、电房和出口的位置，再为每个风险写下具体措施：谁检查电线，谁维护出口，谁处理警报，怎样演练。一周后，厨房故障引起烟雾，员工按流程切断电源并引导旅客撤离。老板终于明白，名单让人知道该担心什么，现场措施和验证才让担心变成保护。风险认知必须落实为适合业务的控制与证据。

## 防御步骤

1. 画出数据流、用户角色、外部服务和信任边界，辨认敏感操作。
2. 对照 2025 类别寻找相关风险，再评估本系统的影响和发生条件。
3. 把风险拆成设计约束、实现控制、部署配置与运营告警，分配负责人。
4. 选择匹配业务的 ASVS 要求与人工检查，覆盖允许、拒绝及异常路径。
5. 上线后跟踪例外、依赖更新和事件，定期重新排序并核验控制。

## 优缺点分析

统一分类便于团队沟通和入门，但粗粒度名单不足以覆盖所有业务滥用、API 或行业需求。只按排名安排投入，容易遗漏低频但高影响的本地风险。

## 应用场景

新项目评审、遗留服务盘点、开发培训都可从 Top 10 开始；支付、医疗和多租户系统还需要更具体的领域要求及数据风险评估。

## 实践建议

为每个相关类别写一条可验证证据，例如“角色甲无法读取角色乙的订单，拒绝事件可关联到请求”。不要把扫描器未报问题当作覆盖证明，也不要将版本号混写为“最新 2021”。

## 🧠 费曼自测

1. Top 10 与完整测试清单有什么区别？
2. 为什么风险排名不能直接决定本公司的修复顺序？
3. 哪个异常路径可能影响授权或事务完整性？
4. 如何证明一条防御措施真正生效？

## 总结

采用明确版本的风险分类，结合资产、设计和实际验证。学习 Top 10 的价值在于推动工程行动，而不是得到“已经安全”的标签。
