# 工具与平台：先定义问题，再选择工具

## 概述

装好扫描器，为什么还找不到跨租户越权？工具擅长观察某一部分证据，业务规则仍要人来定义。本节用学习目标选择平台，避免把“用了工具”当成“防御有效”。

## 资源与用途

| 资源 | 官方入口 | 学习用途 | 边界 |
|---|---|---|---|
| 本仓库标准库实验 | [离线实验说明](../../examples/README.md) | 验证 HMAC、参数化查询和模型外授权 | 合成数据与内存对象，不涉及真实目标 |
| OWASP Web Security Testing Guide | [WSTG 项目](https://owasp.org/www-project-web-security-testing-guide/) | 将应用测试问题组织成检查步骤 | 固定阅读版本，测试必须有明确范围 |
| OWASP Application Security Verification Standard | [ASVS 项目](https://owasp.org/www-project-application-security-verification-standard/) | 定义验收要求和验证证据 | 适用等级由系统风险决定 |
| PortSwigger Web Security Academy | [官方学习平台](https://portswigger.net/web-security) | 在平台提供的练习环境理解 Web 风险与修复 | 只在明确授权的实验空间内练习 |
| OWASP Juice Shop | [官方项目](https://owasp.org/www-project-juice-shop/) | 在隔离训练环境复盘应用防御缺陷 | 有意包含漏洞的教学应用，不应作为真实服务部署 |

入口核验于 **2026-10-04**。平台功能、账户条件和材料可能变化，以官方页面为准。本项目不提供对真实网站的扫描或利用指令。

## 防御验证流程

先用本项目离线实验验证一个机制，再用 WSTG/ASVS 把真实应用的要求写成用例。比如“用户只能看本租户的订单”应有允许本人访问、拒绝他人访问、拒绝跨租户和审计记录四类证据。工具输出的告警要经复现、权限边界分析和修复复测，不能直接当最终风险结论。

为每次授权测试记录目标、时间窗口、数据范围、停止条件和联系人。使用教学靶场时按平台说明隔离网络，采用合成数据；不要把漏洞应用放在可被公网访问的环境。这里不要求安装靶场，完成离线实验就能开始防御学习。

## 📖 寓言故事

维修工带着最好的听诊器检查水管，报告“一切正常”。住户却说厨房仍没有水。另一位工人先画管线图，发现厨房阀门被关上，听诊器并没有覆盖这条支路。仪器没有坏，问题是测量没有对准需求。安全工具也不能替你决定谁应该访问哪份数据；先画边界，再选证据，工具才有用。

## 优缺点与实践建议

标准化指南减少遗漏，教学平台提供直观反馈，但覆盖与生产环境仍有差距。练习后同时记录威胁、根因、控制、误报条件和回归测试，避免只留下“拿到分数”。组织使用平台前检查许可、隐私和数据上传行为。别把日志、令牌或客户数据随意上传到外部分析工具。

## 🧠 费曼自测

1. 业务越权为什么可能被通用扫描器漏掉？
2. 漏洞修复之后，要收集哪些证据才能说明它有效？
3. 教学靶场的环境为什么需要隔离？
