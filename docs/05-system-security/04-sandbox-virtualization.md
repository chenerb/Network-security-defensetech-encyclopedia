# 沙箱与虚拟化隔离

> **学习范围**：本文仅用于教育学习与授权防御；威胁背景服务于防御设计。

## 概述

程序已经放进容器，为什么仍可能影响宿主机？沙箱（Sandbox）是一组限制程序可见资源与可执行操作的机制；虚拟化（Virtualization）提供运行环境抽象。判断隔离强弱，要看实际共享边界与开放通道。

## 历史背景

虚拟机起源于大型计算机的资源共享，后来广泛用于服务器与云平台。容器把操作系统级隔离和应用打包结合起来，提升部署效率。浏览器和文档服务采用多进程沙箱，把复杂输入处理与高价值资源分开；轻量虚拟机则试图兼顾启动速度与独立内核边界。

## 核心原理

容器通常共享宿主机内核。命名空间（Namespace）分隔进程、网络、挂载等资源的视图；控制组（cgroup）管理 CPU、内存等资源；seccomp 限制系统调用，MAC 与能力（Capability）规则限制操作权限。视图分隔、配额和访问控制分别承担不同工作，不能混为一谈。

虚拟机通常运行独立客户机内核，通过虚拟机监控器（Hypervisor）提供虚拟设备。它减少与宿主内核直接共享的接口，但仍有设备模拟、管理面、共享目录和网络等攻击面。独立内核并不等于绝对隔离。

挂载宿主敏感目录、授予特权模式、开放容器管理套接字，可能把宿主管理能力交给容器。分析工作负载时，还必须限制出站网络、临时凭据和数据写回。快照帮助回滚状态，不会自动撤回已发送的数据，也不一定具备备份的独立性和留存能力。

> 🧠 费曼自问：两个房间看不见彼此，与墙能承受火灾，为什么不是同一个保证？

## 通俗解释

容器像同一楼宇的独立房间，虚拟机像各有设施的小院。钥匙、消防、管线和大门仍需管理；给房客整栋楼的总钥匙，会破坏原来设计的边界。

## 📖 寓言故事

城里有两种仓库：一种在大楼中用隔板分间，另一种把货物放进独立院落。商人为了方便搬运，在隔间上接了一根通往总控制室的管道，还把总钥匙留给搬运工。某天，一个隔间的设备失灵，搬运工通过管道改动了整楼的电闸。老板惊讶地说：“明明每间都有门！”工程师检查后指出，门只能管住走廊，管道却直通控制室。于是普通货物仍用隔间，危险货物改放院落，两种仓库都撤掉总钥匙、限制管道并设置容量上限。故事提醒我们：隔离能力取决于共享设施和例外通道，不取决于房间叫“容器”还是“虚拟机”。

## 防御步骤

1. 先定义工作负载是否互信、处理什么数据、失陷会影响谁，据此选择进程、容器或虚拟机边界。
2. 使用精简且受支持的基础环境，固定镜像版本并验证来源，持续更新宿主与客户机。
3. 默认低权限、只读文件系统、最少挂载和能力，避免特权模式与管理套接字暴露。
4. 配置资源上限、系统调用策略和网络出口规则，为必要例外设定明确目的与期限。
5. 分离管理面和业务面，监测策略变化、异常资源使用，验证销毁和恢复后的残留数据处理。

## 优缺点分析

容器启动快、密度高，但共享内核需要认真治理；虚拟机一般边界更独立，却占用更多资源并增加客户机维护。严格沙箱可能阻碍正常调用，需要按业务验证，不能为兼容而无限增加权限。

## 应用场景

同一团队的常规服务可用加固容器；互不信任租户、风险较高的解析任务可评估虚拟机或额外隔离层；任何选择都需要独立账号、网络策略和管理面保护。

## 实践建议

用配置清单检查宿主挂载、管理 API、设备映射、出口与资源上限。只在授权测试环境验证拒绝路径。把“恢复快照”与“从独立备份恢复”分别演练，确认数据一致性、凭据失效和外部系统状态。

## 总结

隔离应与威胁模型匹配。减少共享接口、取消危险例外，并持续验证权限、资源和网络限制，才能把“有沙箱”变成可证明的防御能力。
