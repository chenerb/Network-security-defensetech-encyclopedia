# 操作系统安全机制

> **学习范围**：本文仅用于教育学习与授权防御；威胁背景服务于防御设计。

## 概述

为什么一个普通文档转换程序出了错，可能连服务器上的其他业务也受影响？操作系统（Operating System，OS）负责把处理器、内存、文件和设备分给程序。系统安全首先要明确“谁以什么身份，能对哪个资源做什么”，再让每次访问都经过检查。

## 历史背景

早期单用户计算机很少考虑互不信任的程序。多用户分时系统推动了用户身份、文件权限和进程隔离；后来网络服务、移动应用与云平台又推动了强制访问控制、应用签名和可信启动。今天的加固既处理内核漏洞，也处理管理员配置错误。

## 核心原理

用户态与内核态是硬件支持的权限分层：应用通过系统调用请求服务，内核检查后执行。虚拟内存通过页表把进程地址映射到物理内存，通常阻止进程随意读取他人的地址；共享内存和调试接口属于需要额外授权的例外。

自主访问控制（Discretionary Access Control，DAC）允许资源所有者分配权限；强制访问控制（Mandatory Access Control，MAC）把进程和资源标签纳入统一策略，进程即使取得某些文件权限，也可能被 SELinux 等机制拒绝。管理员权限不是万能安全工具，而是扩大误操作与失陷影响的能力。

可信启动检查启动链的签名与策略，帮助阻止未经授权的启动组件；它不能证明应用没有逻辑漏洞。审计记录身份、时间、对象、操作与结果，只有集中保存、限制篡改并有人响应，才形成有效的证据链。

> 🧠 费曼自问：为什么“账号能读这个文件”和“这个进程能读这个文件”可以有不同答案？

## 通俗解释

操作系统像公寓管理员：门牌是资源标识，钥匙是权限，前台负责检查，摄像头负责留证。门锁负责阻止访问，摄像头负责发现与解释，两者不能互相替代。

## 📖 寓言故事

灯塔城有一座共享工坊。木匠只拿到木料间的钥匙，画师只拿到颜料间的钥匙。一天，木匠的学徒收到一张伪造的工作单，要求他去账房取走工资册。学徒虽不会辨认伪造文字，却发现自己的钥匙打不开账房。管家随后规定，搬运木料的车也不能进入账房走廊；即使有人借来了门钥匙，车仍会被拦下。夜里，巡查员从登记簿发现连续开门失败，及时通知主人。工坊没有指望每个人永远不犯错，而是把钥匙、走廊规则与登记簿结合起来。系统防御的寓意是：限制权限、约束进程，并让异常行为留下可用证据。

## 防御步骤

1. 列出服务、用户、敏感目录与管理入口，删掉不需要的服务和默认账号。
2. 日常账号与管理账号分离；服务以独立低权限身份运行，只开放必要文件和设备。
3. 采用受支持的系统版本，先在代表性环境验证补丁，再按暴露程度安排发布与回滚。
4. 为关键服务建立 MAC 策略和安全配置基线，记录例外的负责人及到期时间。
5. 集中保存登录、提权、策略变更和关键文件访问事件；定期验证告警与恢复流程。

## 优缺点分析

最小权限和 MAC 能降低单个进程失陷的影响，集中审计有助于定位问题；代价是策略维护、兼容性测试和运营成本。策略过宽失去价值，过窄会造成业务故障，因此应先观察正常工作流，再逐步收紧。

## 应用场景

数据库主机重点限制服务账号和数据目录；终端重点保护更新链、用户权限和应用安装；多人共用服务器还要限制调试、临时文件和共享资源。网络隔离与 OS 权限共同覆盖不同入口。

## 实践建议

在授权测试环境做一张“身份—资源—操作”矩阵，分别验证允许与拒绝路径，并检查日志是否包含足够上下文。不要为了消除拒绝日志直接关闭 MAC；先确认访问确有业务必要，再调整最小规则。备份与回滚演练必须与补丁计划一起准备。

## 总结

系统安全把身份、权限、隔离、完整性与审计连成一条链。先缩小可访问资源，再管理更新和配置，最后用验证与日志确认控制在真实工作流中有效。
