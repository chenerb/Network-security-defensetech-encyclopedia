# 应急响应与数字取证

## 概述

发现服务器异常后，立即重装是“反应快”，还是把线索一并抹掉？应急响应（Incident Response）控制损害并恢复业务；数字取证（Digital Forensics）以可追踪的方法保全、分析和解释证据。两者协作，但目标与优先级可能不同。

> 本节仅用于教育学习与合法防御；取证范围和通知责任应按组织授权与适用规则确定。

## 历史背景

2012 年的 NIST SP 800-61 Rev. 2 常用准备、检测分析、遏制根除恢复、事后活动讲解响应。2025 年 4 月 3 日发布的 [Rev. 3](https://csrc.nist.gov/pubs/sp/800/61/r3/final) 已替代 Rev. 2，将响应纳入 CSF 2.0 的整体风险管理：治理、识别、保护支撑准备，检测、响应、恢复处理事故，改进贯穿各环节。旧流程仍便于教学，但不能冒称最新指南的原始结构。

## 核心原理

先建立影响与证据可信度：哪些资产受影响、哪些凭据可能暴露、是否仍在扩散、目前结论来自何处。遏制（Containment）限制进一步损害；根除（Eradication）处理原因；恢复（Recovery）在验证后重建服务。封禁一次连接不代表入口或持久化问题已消除。

[NIST SP 800-86](https://csrc.nist.gov/pubs/sp/800/86/final) 从 IT 视角介绍收集、检查、分析、报告。证据保管链（Chain of Custody）记录采集人、时间、对象、方法、哈希、转交及访问；哈希能发现记录后的变化，不能单独证明采集前真实，也不能替代授权。

| 对象 | 处置注意 | 需要保留 |
|---|---|---|
| 内存、进程、连接 | 易失，关机可能丢失 | 采集工具版本、时间、影响 |
| 磁盘与日志 | 原件可能继续变化 | 受控副本、校验值、访问记录 |
| 云资源 | 快照不含所有远端审计 | 租户、区域、资源版本、控制面日志 |
| 凭据 | 隔离主机不能撤销已泄露令牌 | 撤销、轮换与依赖恢复记录 |

恢复目标须由业务影响分析确定：**恢复时间目标（RTO）**限定资源恢复可用的时长目标，**恢复点目标（RPO）**说明需要恢复到中断前哪个数据时间点，常用可容忍的数据回退时长表达。例如 RTO 两小时与 RPO 十五分钟是两个不同目标，需以恢复演练核对实际耗时和数据缺口；备份任务成功不等于达到目标。定义依据 [NIST SP 800-34 Rev.1，2010 年更新版](https://csrc.nist.gov/pubs/sp/800/34/r1/upd1/final)，不将旧指南称作新发布标准。

> 🧠 **费曼自问**：为什么相同文件的哈希一致，还不能证明它来自哪台机器？

## 通俗解释

消防员先救人控火，调查员寻找起火原因。证据袋像带签收记录的包裹：封条和校验值保护内容，交接单解释由谁、何时、从哪里取得。

## 📖 寓言故事

面包房半夜冒烟，学徒急忙把烤炉拆净，烟暂时没了。老板赶来问：“是电线坏了，还是有人忘记关炉？”学徒指着一堆混在一起的零件，谁也说不清。隔壁消防员教他先拉开人员与危险区，判断能否安全断电；另一人拍下现场，标记零件位置，把易丢失的值班记录封存。第二次发现焦味时，两人一边阻止火势蔓延，一边按顺序留证。修好的炉子经过试运行才重开店。快速清理只能让现场看起来恢复，保全线索并验证原因才有机会避免再次起火。

## 防御步骤 / 工作流程

1. 平时确定响应负责人、联络链、分级标准、隔离权限、证据留存和恢复预案，做桌面演练。
2. 接报后记录原始告警与时间，核验异常，评估业务与安全影响，启动相应级别并保留判断依据。
3. 在安全与持续损害约束下选择隔离、限流、账号停用等遏制；能并行时安排人员保全易失证据，记录操作副作用。不能为等待完美证据放任危害。
4. 在获授权的范围采集受控副本，生成校验值并记交接；分析副本，将事实、推断和未知分别写入时间线。
5. 修复入口、清除影响、轮换凭据；用可信备份或基线恢复，验证完整性、业务功能和监控，分阶段回流。
6. 按组织流程评估通知责任、形成报告与复盘，把检测、配置、培训缺口转成有期限的改进任务。

## 优缺点分析

### 优点

预案减少混乱，保全证据支持根因和影响判断，验证恢复可减少二次事故。

### 缺点

在线取证会改变现场；完整采集可能占用资源或扩大敏感数据留存。隔离也可能中断关键业务，必须记录权衡并由适当人员决策。

## 应用场景

账号失窃、数据异常导出、勒索软件疑似活动、云配置被篡改均适用。涉及生命安全的环境优先消除即时危险，同时尽可能保留决策证据。

## 实践建议

演练时用合成日志练习“一条告警→三项待核事实→遏制选择→恢复验收”，不要接触真实受害数据。报告使用“观察到”“推测”“尚未排除”表达证据强度；删除一个异常文件、恢复一个页面均不能自动宣布事故结束。

## 🧠 费曼自测

1. 遏制、根除、恢复分别解决哪个问题？
2. 为什么重启前要考虑内存与连接信息？
3. 哈希、保管链和原始来源各证明什么？
4. 业务恢复后还需完成哪些工作？

## 总结

响应要同时控制损害、保护证据和验证恢复。先后顺序由危险程度与证据易失性决定；全过程可记录、可交接，结论才可信。
