# 内容检查工具

在仓库根目录运行，Python 3.9+ 即可，无第三方依赖，也不请求网络：

```bash
python3 scripts/check_content.py
python3 scripts/check_content.py --json
python3 -m unittest discover -s tests -v
```

默认从脚本所在仓库开始检查，可用 `--root PATH` 检查另一份文档目录。成功退出码为 `0`；存在内容问题为 `1`；命令参数不合法为 `2`。JSON 包含 Markdown 文件数、正文数、试卷套数与带源文件行号的错误列表。

## 检查范围

- 本地内联链接、图片、显式引用式链接、带空格和 URL 编码路径；支持 `<路径>` 后的链接 title，以及从仓库根目录解析的 `/路径`。
- Markdown 标题锚点保留 inline code 中的标题文字；重复标题及已有后缀之间的冲突按全文已生成锚点继续编号。
- 排除 fenced code 和 inline code 中的示例链接，检查未闭合的代码块；无效 URL 报告源行号并继续检查，不让 JSON 输出中断。
- 第一至九章的教学模块和最低实质内容长度。
- 全十章每节小测与每章综合卷、挑战卷、压力面是否存在；题目/解析是否配对，主问题编号是否连续且一致，题量是否在约定范围内。
- 解析中的考点分布表；本地链接不能越出仓库。

这个工具针对本仓库采用的 Markdown 子集，不是完整的 CommonMark 渲染器。锚点按 GitHub 常见标题规则生成；更复杂的 HTML、自定义标题 ID 和渲染器特性需人工核对。

## 仍需内容评审的项目

工具不能证明技术建议正确、参考来源仍可访问、故事足够清楚、选择题唯一正确或场景分值合计正确。外部页面不在离线检查中访问；编辑时应实际查阅原始资料，记录版本与核验日期。统计总数来自当前文件，不能单独证明目录规划合理。

新增检查行为先用临时目录夹具写测试，确认能捕获具体错误，再实现规则。实验测试关注篡改、越权和畸形输入等行为，不用文本快照代替运行结果。
